# План отчётности «Сервисного центра» — по образцу сводного отчёта КЦ РусГидро

> 20.06.2026. Цель: автоматизировать в разделе «Сервисный центр» (netservice)
> ручной недельный Excel-отчёт КЦ, который сейчас собирается из 4 источников —
> HubEx, телефония МегаФон, мессенджеры, таблица контакт-центра. Основано на
> разборе реального файла «Отчет_по_статистике_заявок_в_Хабикс_за_08-14 июня».

## 1. Что собой представляет образцовый отчёт (10 листов)

| Лист | Содержание | Источник |
|------|-----------|----------|
| **Отчёт (Табл.1)** | Матрица **вид работ × тип заявки** по неделям: абс. кол-во + доля % + дельта к пред. периоду; подытоги по группам (Работы по ЭЗС / Консультация / ПО / Гарант. ремонт) | HubEx |
| **Лист1 / Лист2** | Сырьё заявок (выгрузка HubEx): Number, WorkType, TaskType, Notes, Asset, Deadline, Criticality, Assignee, даты, CompanyName, координаты, ContactPhone, RequestedBy | HubEx |
| **Операторы (Табл.3)** | По дням: число операторов, принятые звонки, пропущенные звонки, ИТОГО, среднее | Телефония МегаФон |
| **Принятые / Пропущенные** | Сырьё звонков: тип, номер клиента, оператор, через какой номер, дата/время, **ожидание**, **длительность**, оценка | Телефония МегаФон |
| **Расшифровки по табл.1** | Для вида работ (напр. «Станция офлайн») — производитель ЭЗС × номера станций | HubEx + парк |
| **Производители** | Парк ЭЗС по брендам (S/N): ПСС 128, FORA 44, Parus 40, Kostad 29 … итого 342 | Реестр оборудования |
| Лист3 | Инструкция пересчёта (правила агрегации) | — |

**Главный смысл отчёта** — «понимание состояния обслуживания»: что чаще ломается
(виды работ), куда движется тренд (недельная динамика + дельты), какова нагрузка
на телефонию (звонки/потери), какие производители/объекты проблемные.

## 3. Каталог отчётов раздела (что добавляем в «Сервисный центр»)

### Отчёт R1 — «Структура заявок» (= Табл.1) ⭐ ГЛАВНЫЙ
Матрица **вид работ × период (неделя)**: абс. + доля % + **дельта к пред. периоду**,
сгруппировано по типу заявки (Работы по ЭЗС / Консультация / ПО / Гарант. ремонт) с
подытогами. Фильтры-разрезы: критичность, регион, производитель, подрядчик.
- Данные: `hubex_tasks` (есть). Эндпоинт `GET /netservice/reports/work-type-matrix
  ?granularity=week&from&to&group_by=task_type`.
- Это автоматизация самого трудоёмкого листа отчёта.

### Отчёт R2 — «Расшифровка по производителям»
Для выбранного вида работ — производитель ЭЗС × число станций/заявок (как лист
«Расшифровки»). Плюс надёжность: доля отказов на единицу парка.
- Данные: `hubex_tasks` JOIN `service_locations.metadata.manufacturer`. Эндпоинт
  `GET /netservice/reports/work-type-by-manufacturer?work_type=&from&to`.

### Отчёт R3 — «Парк оборудования»
Кол-во ЭЗС по производителям (= лист «Производители»), статус на балансе, средняя
наработка между отказами (MTBF) по бренду.
- Данные: `service_locations` (manufacturer) + `hubex_tasks` для отказов.

### Отчёт R4 — «Телефония КЦ» (= Табл.3 + Принятые/Пропущенные) — НОВЫЙ ИСТОЧНИК
По дням/неделям: число операторов, **принятые** / **пропущенные** звонки, % потерь,
**ASA** (среднее ожидание), **AHT** (средняя длительность), оценки. Пики по часам.
- Данные: новый источник `telephony_megafon` → таблица `telephony_calls`.
- Ввод данных (фаза А): **импорт Excel-выгрузки** листов «Принятые»/«Пропущенные»
  (тип/номер/оператор/дата/время/ожидание/длительность/оценка). Фаза Б: API МегаФон.

### Отчёт R5 — «Сквозной контур обращений» (звонок → заявка → ремонт)
Объединяет линии: обращение приходит звонком (МегаФон) / мессенджером / в таблицу КЦ
→ оператор заводит заявку HubEx (в выгрузке `RequestedBy = «Оператор Колл-центра»`,
`ContactPhone`) → выезд/ремонт. Метрики: **конверсия звонок→заявка**, E2E-SLA
от звонка до закрытия, **потери на стыках** (звонок без заявки; заявка без обращения).
- Данные: `telephony_calls` + `messenger_messages` + `cc_records` + `hubex_tasks`,
  сшивка в унифицированный `support_cases` по телефону/времени/оператору.

## 4. Новые сущности и источники (для R4–R5)

- **`telephony_calls`** (источник `telephony_megafon`): `direction` (входящий/
  пропущенный), `client_phone`, `operator`, `via_number`, `started_at`, `wait_sec`,
  `duration_sec`, `rating`, `note`, `raw`. Ключ идемпотентности
  `(company_id, client_phone, started_at)`.
- **`messenger_messages`** (источник `messengers`): канал (TG/WA/…), `chat_id`,
  `client`, `received_at`, `text`, `linked_case_id`.
- **`cc_records`** (таблица контакт-центра): своя структура обращений КЦ (уточнить
  формат у РусГидро) — `ext_id`, классификация, `opened_at`, `operator`, `linked_case_id`.
- **`support_cases` / `support_case_links`** — унифицированное обращение поверх всех
  источников (как в HUBEX_MANAGEMENT_REPORTING §1.1), с графом звонок→обращение→заявка.
- **Парк/производитель как разрез**: промо-поле `manufacturer` на точке (есть в
  metadata) + при синке `hubex_tasks` денормализовать `manufacturer` в строку заявки
  (для быстрых матриц R1/R2 без джойна).

## 5. Поэтапность

**Этап 1 — HubEx-отчёты (на текущих данных, без новых источников):**
1. Денормализовать в `hubex_tasks` поле `manufacturer` (резолв через точку при синке).
2. Эндпоинты R1 (work-type-matrix: неделя × вид работ, абс/доля/дельта, группировка
   по типу заявки) и R2/R3 (по производителям, парк).
3. UI: режим «Отчёты» в разделе — таблица-матрица R1 (как Табл.1) + расшифровки R2 +
   парк R3. Экспорт в Excel (повторяет формат первоисточника).

**Этап 2 — телефония МегаФон:**
4. Источник `telephony_megafon`, таблица `telephony_calls`, **импорт Excel**
   «Принятые»/«Пропущенные» (drag-drop на странице источника) → отчёт R4 (операторы,
   принятые/пропущенные, ASA/AHT, % потерь). Позже — API МегаФон.

**Этап 3 — сквозной контур:**
5. `messenger_messages` + `cc_records` + `support_cases`; сшивка звонок→заявка по
   `ContactPhone`/времени/оператору; отчёт R5 (конверсия, E2E-SLA, потери на стыках).
6. Авто-сборка недельного отчёта (PDF/Excel) = полная замена ручного файла.

## 6. Технические заметки
- Период отчёта — **недельный (пн–вс)**; дельты считаются к предыдущей неделе.
- Группы видов работ берём по `task_type` (Работы по ЭЗС / Консультация / Работы по ПО
  / Гарантийный ремонт) — как в подытогах Табл.1.
- «Старые периоды не пересчитывать» (правило из Лист3) ⇒ снапшоты недель можно
  кэшировать; живой пересчёт — только текущая неделя.
- Парк 342 (отчёт) vs 463 объекта (наш синк) — расхождение «на балансе» vs все asset'ы;
  для R3 фильтровать по статусу/наличию S/N.
- Маппинг кодов коннекторов в названия (0/1/3/6 → Type2/CCS/CHAdeMO/GB/T) — уточнить
  справочник у РусГидро (нужно и для таблицы точек).
