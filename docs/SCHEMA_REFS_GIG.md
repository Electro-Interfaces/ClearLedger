## 0. Принцип: УНИВЕРСАЛЬНЫЙ справочник (берём ВСЕ поля)

Справочники контрагентов и договоров — **универсальные**, не привязаны к ГИГ.
ГИГ (БП 3.0) — лишь первый источник-пример; модель должна принять любую 1С
(БП/УТ/КА), у которой свой набор реквизитов. Поэтому:

- **Берём ВСЕ реквизиты** контрагента и договора, какие есть в 1С (без отбора
  «нужное/ненужное»). Запрос — все реквизиты сущности (через `describe_entity`
  динамически, не фиксированный `$select`).
- **Хранение = raw + promo**: полный снимок всех полей 1С → колонка `raw` (JSONB,
  как пришло из источника, L1 RAW). Поверх — **промо-колонки** (типизированные)
  для полей, по которым идут сверка/фильтры/индексы/связи. Промо — это НЕ
  ограничение охвата, а ускорение доступа; остальное всегда доступно из `raw`.
- Промо-набор расширяется по мере надобности без потери данных (всё уже в `raw`).
- Связи (контрагент→договор, организация) держим по `external_ref` (Ref_Key),
  устойчиво к мультиисточнику и мультитенантности (`company_id` уже в моделях).

Таблицы ниже — это **приоритет промотирования** (что вынести в колонки), а НЕ
список «что забираем». Забираем всё; в `raw` попадает каждый реквизит.

## 2a. Связь договоров и контрагентов с торговыми точками (НАШ слой)

Решение МАГа 18.06.2026. Связи договор↔точка **нет в 1С** — это надстройка
TradeLedger над импортированными НСИ. Договор из 1С приходит «голым» (Владелец=
контрагент, Организация); охват по точкам проставляется у нас.

**Область действия (scope) — атрибут ДОГОВОРА; точки контрагента = производное**
(объединение охватов его договоров). Прямой связи контрагент↔точка НЕТ — только
через договоры (решение: один источник истины).

| `Contract.scope_type` | Смысл | Точки |
|---|---|---|
| `company` | вся компания — все текущие **и будущие** точки | связей нет (вычисляется) |
| `locations` | конкретный ad-hoc набор точек (1…N) | M2M `contract_locations` |
| `unassigned` | импортирован, не распределён (**дефолт после pull**) | нет |

«1 точка» = `locations` с одним элементом. «Группа точек» = ad-hoc набор в M2M
(именованных переиспользуемых групп НЕТ — решение МАГа; добавить позже при нужде).
`company` ≠ «выбрать все точки галочками»: company-договор автоматически охватывает
новые точки.

**Таблица `contract_locations`**: `id`, `contract_id`→contracts, `location_id`→
service_locations, `company_id` (изоляция), `note?`, `created_at`. UNIQUE
`(contract_id, location_id)`. Для `company`/`unassigned` — пустая.

**Запросы (оба направления, то что нужно в UI):**
- *Контрагент → точки*: есть `company`-договор → «Вся компания»; иначе union точек
  его `locations`-договоров (группировка по договору) + счётчик `unassigned`.
- *Точка → договоры*: все `company`-договоры этой компании ∪ `locations`-договоры,
  где точка ∈ `contract_locations`. Контрагенты = DISTINCT владельцы этих договоров.

**UX**: карточка контрагента — блок «Где работаем» (бейдж «Вся компания» / список
точек по договорам); карточка точки — блок «Договоры» (адресные + общекомпанейские,
помечены) с контрагентом и видом; форма договора — переключатель «Вся компания /
Выбранные точки» + мультиселект; экран-очередь «нераспределённые договоры» после импорта.

## 3. Что менять в коде (для реализации)

**Backend** (`server/app/services/onec/`, `routers/`, `models.py`):
1. **Полный fetch (универсально)**: select по всем реквизитам сущности через
   `describe_entity` (а не фиксированный `COUNTERPARTY_SELECT`/список). Так модель
   принимает любую конфигурацию 1С, не только БП ГИГ.
2. **Колонка `raw` (JSONB)** в `Counterparty` и `Contract` — полный снимок всех
   полей источника (L1 RAW). Промо-колонки заполняются из `raw` при апсёрте.
3. `sync_service.py`: новый `_sync_contracts()` + `ENTITY_CONTRACTS` в `sync_catalogs`.
   Резолв `Владелец` (Ref_Key контрагента) → `Counterparty.external_ref`; апсёрт
   договора по `external_ref`. Заполнять `Contract.external_ref`.
4. Миграция моделей (`database.py` идемпотентный ALTER + `models.py`):
   - `Counterparty`: `+raw JSONB`, `full_name`, `okpo?`, `head_ref?`; `type` из ЮрФизЛицо/ИП.
   - `Contract`: `+raw JSONB`, `kind`, `currency`, `valid_until?`, `is_closed`; `counterparty_id`=GUID;
     `+scope_type` (`company`/`locations`/`unassigned`, дефолт `unassigned` при pull).
   - Новая модель `ContractLocation` (M2M `contract_locations`, см. §2a).
5. Эндпоинты связей: `GET /contracts?counterparty_id=`, `GET /contracts?location_id=`,
   `GET /counterparties/{id}/locations` (агрегат), `GET /locations/{id}/contracts`;
   PUT охвата договора (`scope_type` + список точек). Отдавать `raw` опционально.

**Frontend** (всё read-only сейчас):
6. CRUD-формы контрагента/договора + привязка договора к контрагенту (dropdown) +
   переключатель охвата «Вся компания / Выбранные точки» + мультиселект точек.
7. Блок «Где работаем» в карточке контрагента; блок «Договоры» в карточке точки
   (`LocationCard`/страница точки); экран-очередь «нераспределённые договоры».
8. Разрез сверки НСИ: контрагенты/договоры клиента ↔ 1С (по ИНН / Ref_Key); UI слияния
   дублей (бэкенд `merge` уже есть).
