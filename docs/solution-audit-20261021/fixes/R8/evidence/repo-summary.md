Линтера Python в проекте нет, поэтому третьей проверки здесь не появляется.

на `fe94f3f5`; оба дерева заморожены, чтобы правка не задела свой же замер.

### Ошибка на teardown — отказ контура, не кода

В обоих прогонах ровно один файл показал `.....E`: все тесты в нём прошли, ошибка
случилась в уборке, где `conftest` делает `DROP SCHEMA public CASCADE`. Ошибка одна и
та же:

```
asyncpg.exceptions.OutOfMemoryError: out of shared memory
HINT:  You might need to increase max_locks_per_transaction.
```

Причина — мой контур: три тестовые базы (`before`, `after`, `red`) жили в одном
контейнере `postgres:16` с `max_locks_per_transaction = 64`, и одновременные
`DROP SCHEMA` на схемах в сотни таблиц исчерпывали таблицу блокировок. Что именно
останется без слотов — вопрос совпадения прогонов во времени, и файлы в двух прогонах
поэтому разные.

Лимит поднят до 512, оба файла перепрогнаны по одному, каждый в своём дереве —
**по 5 пройденных, без ошибок** (`repo-tests-teardown-rerun.txt`). Третьим прогоном
проверен и `test_location_types.py` на дереве «после»: тоже зелёный.

### Прежние падения, которые были до правки и остались

Ни одного падения по коду в наборе нет — ни до, ни после. Прежнее состояние
репозитория, которое правка не трогала:

* **карантин из трёх файлов** (`tests/quarantine.txt`, причины и владельцы записаны
  там же): `test_edge_to_bp_flow.py` — разбор пакета идёт через COM-объект Windows;
  `test_accounting_egress.py` и `test_accounting_group_v3.py` — незавершённая работа по
  бухгалтерскому контуру от 23.08.2026;
* **`test_store_receipt_ingest.py` отключает себя сам**, когда окружения нет — об этом
  `run_ci.sh` говорит вслух отдельной строкой: «проверок не было». В CI этот файл
  гоняется, и зелёный прогон здесь его не заменяет.
