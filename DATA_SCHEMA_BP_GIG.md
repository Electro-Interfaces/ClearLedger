## 1. Поток A — Учётная политика и реквизиты

### Что забираем

| OData-сущность | Назначение | Частота |
|---|---|---|
| `Catalog_Организации?$filter=ИНН eq '7839440090'` | Реквизиты ГИГ (ИНН/КПП/ОГРН/адрес/телефон/банк, налоговый режим) | Раз в сутки |
| `InformationRegister_УчетнаяПолитикаОрганизаций` | Метод оценки запасов (FIFO/средняя), ставка УСН, режим НДС, ведёт ли раздельный учёт, упрощёнка/общий | При изменении ИЛИ раз в сутки |
| `InformationRegister_ДатыЗапретаИзменения` (или Constants/функц. опции) | Какие периоды закрыты (дата запрета редактирования) | Раз в час — это критично для понимания "что эталон, а что нет" |
| `Catalog_ОтветственныеЛицаОрганизаций` | ФИО руководителя/главбуха для подписи документов и отчётов | Раз в сутки |
| `Catalog_БанковскиеСчета?$filter=Владелец/ИНН eq '7839440090'` | Расчётные счета ГИГ | Раз в сутки |

### Куда в ClearLedger

| Из БП | Поле/модель ClearLedger |
|---|---|
| Catalog_Организации (запись ГИГ) | `Organization` (`external_ref` = Ref_Key, остальные поля 1:1) |
| УчетнаяПолитика.МетодОценкиТМЗ | `AccountingPolicy.inventory_method` (новая модель) |
| УчетнаяПолитика.РежимНДС | `AccountingPolicy.vat_mode` |
| УчетнаяПолитика.СпособРаспределенияНДС | `AccountingPolicy.vat_distribution` |
| ДатыЗапретаИзменения | `Period.status = 'closed'` (для всех периодов ≤ даты запрета) |
| ОтветственныеЛица | `Organization.metadata.responsible_persons` (JSONB) |
| БанковскиеСчета | `BankAccount` (с `external_ref`) |

### Новые модели бэка

```python
class AccountingPolicy(Base):
    __tablename__ = "accounting_policies"
    id: uuid
    company_id: FK(companies.id)
    organization_id: FK(organizations.id)
    effective_from: date          # с какой даты действует
    effective_to: date | None     # до какой даты
    inventory_method: str         # 'fifo' | 'average' | 'fifo_by_lot'
    vat_mode: str                 # 'general' | 'simplified' | 'no_vat'
    vat_distribution: str         # 'proportional' | 'manual' | 'none'
    accounting_chart_version: str # «Типовой план счетов БП 3.0»
    raw_data: JSONB               # полная выгрузка из 1С для аудита
    external_ref: str | None       # Ref_Key записи учётной политики
    created_at, updated_at
```

## 2. Поток B — Сменные отчёты (ОРП)

### Что забираем

#### Шапка документа

```
GET /Document_ОтчетОРозничныхПродажах?
    $filter=Организация/ИНН eq '7839440090'
         and Дата ge datetime'2026-01-01T00:00:00'
         and Проведен eq true
    $expand=Товары,Оплата,АгентскиеУслуги,Возвраты,СведенияПрослеживаемости
    $format=json
```

| Реквизит шапки | Значение | Маппинг |
|---|---|---|
| `Ref_Key` | GUID документа | `external_ref` |
| `Number` | Номер документа | `AccountingDoc.number` |
| `Date` | Дата/время документа | `AccountingDoc.date` |
| `Organization_Key` | GUID организации | `Organization.external_ref` (matchим) |
| `Склад_Key` | GUID склада (АЗС) | `Warehouse.external_ref` |
| `КассаККМ_Key` | GUID кассы | `KktMachine` (новая модель) |
| `Подразделение_Key` | GUID подразделения | `Department` (новая модель, опц.) |
| `Контрагент_Key` | «Розничный покупатель» (типовой контрагент) | `Counterparty.external_ref` |
| `ВидОперации` | `ОтчетККМОПродажах` / `НТТО` | `AccountingDoc.operation_kind` |
| `Posted` | Проведён ли | `AccountingDoc.is_posted` |

#### Табличная часть «Товары» (или «АгентскиеУслуги» для топлива от поставщиков)

| Поле | Маппинг |
|---|---|
| `LineNumber` | `AccountingDocLine.line_no` |
| `Номенклатура_Key` | `Nomenclature.external_ref` |
| `Количество` | `quantity` |
| `Цена` | `price` |
| `Сумма` | `amount` |
| `СтавкаНДС` | `vat_rate` (Без НДС / 0 / 10 / 18 / 20 / 22) |
| `СуммаНДС` | `vat_amount` |
| `СчетУчета_Key` | `Account.external_ref` (обычно 41.02) |
| `СчетДоходов_Key` | обычно 90.01.1 |
| `СчетРасходов_Key` | обычно 90.02.1 |
| `СубконтоДт1/Кт1` | для аналитики (Номенклатура / Контрагент / Договор) |

#### Табличная часть «Оплата»

| Поле | Маппинг |
|---|---|
| `ВидОплаты_Key` | `PaymentChannel` (Наличные / Платёжная карта / Талон / Безналичный счёт) |
| `Сумма` | `amount` |
| `СчетУчетаКассы_Key` | обычно 50.01 (касса) / 57.03 (платёжные карты в пути) |
| `Покупатель_Key` | контрагент платежа (обычно «Розничный покупатель» или конкретный по корпкартам) |

#### Проводки (из регистра бухгалтерии)

OData отдаёт регистр накопления отдельно:

```
GET /AccumulationRegister_Хозрасчетный?
    $filter=Регистратор_Key eq guid'<Ref_Key документа>'
```

Получаем все проводки этого документа:
- **90.02.1 / 41.02** — списание себестоимости
- **62.Р / 90.01.1** — выручка
- **50.01 / 62.Р** — наличные в кассу
- **57.03 / 62.Р** — безналичные в пути (карты, корпоратив)
- **90.03 / 68.02** — НДС начисленный

Каждая проводка → строка в `AccountingEntry`:

```python
class AccountingEntry(Base):
    __tablename__ = "accounting_entries"
    id: uuid
    company_id: FK
    document_id: FK(accounting_docs.id)
    line_no: int
    entry_date: datetime
    debit_account: str         # «41.02»
    debit_subconto1: str | None # GUID/код субконто
    debit_subconto2: str | None
    debit_subconto3: str | None
    credit_account: str        # «60.01»
    credit_subconto1: str | None
    credit_subconto2: str | None
    credit_subconto3: str | None
    amount: Numeric(15, 2)
    quantity: Numeric(15, 3) | None
    currency_amount: Numeric(15, 2) | None  # для валютных
    content: str               # «Поступление товара»
    external_ref: str          # Ref_Key проводки в БП
```

### Что важно у ОРП в БП ГИГ

- **ВидОперации=ОтчетККМОПродажах** для топлива (а не НТТО). На стенде проверено в коммите v5.6.
- НДС 22% (а не 20%) — Россия 2026, ставки УСН/общая см. учётную политику.
- В шапке указан **Контрагент = «Розничный покупатель»** (типовой служебный контрагент, GUID `0000-0000-0000-0000-` или похожий).
- Топливо может быть как «Товары» (своё), так и «АгентскиеУслуги» (от поставщика) — нужно различать.

## 3. Поток C — Поступления (ПТУ)

### Что забираем

```
GET /Document_ПоступлениеТоваровУслуг?
    $filter=Организация/ИНН eq '7839440090'
         and Дата ge datetime'2026-01-01T00:00:00'
         and Проведен eq true
    $expand=Товары,Услуги,СведенияПрослеживаемости
    $format=json
```

#### Шапка ПТУ

| Реквизит | Маппинг |
|---|---|
| `Ref_Key`, `Number`, `Date` | стандартные |
| `Контрагент_Key` | `Counterparty.external_ref` (поставщик нефтепродуктов) |
| `Договор_Key` | `Contract.external_ref` |
| `Склад_Key` | АЗС или общий склад |
| `ВходящийНомер` | Номер ТТН поставщика |
| `ВходящаяДата` | Дата ТТН |
| `ВидОперации` | `Товары` / `УслугиТоварыКомиссия` |
| `СуммаДокумента` | Итог |
| `Комментарий` | Может содержать ОСЭ_Номер / ИсточникUUID (если из расширения) |

#### ТЧ «Товары»

| Поле | Маппинг |
|---|---|
| `Номенклатура_Key` | `Nomenclature.external_ref` (АИ-92 / АИ-95 / ДТ) |
| `Количество` | литры |
| `Цена` | цена за литр |
| `Сумма` | сумма без НДС |
| `СтавкаНДС` | |
| `СуммаНДС` | |
| `Всего` | с НДС |
| `СчетУчета_Key` | 41.02 |
| `СчетУчетаНДС_Key` | 19.03 |

#### Проводки ПТУ (типовые)

- **41.02 / 60.01** — товар (количество литров идёт в субконто)
- **19.03 / 60.01** — входной НДС
- (Отдельный документ) **68.02 / 19.03** — НДС к вычету (после регистрации СчетФактураПолученный)

### Связанные документы

| Документ БП | Маппинг | Когда забирать |
|---|---|---|
| `Document_СчетФактураПолученный` (linked by `Основание_Key`) | `AccountingDoc` тип `invoice_received` | Раз в сутки (либо вместе с ПТУ через $expand) |
| `Document_КорректировкаПоступления` | `AccountingDoc` тип `receipt_correction` | Только если изменился ПТУ |
| `Document_СписаниеТоваров` (для усушек/потерь нефти) | `AccountingDoc` тип `writeoff` | По мере появления |

### Особенности ПТУ ГИГ

- **НДС 22%** в большинстве позиций (Россия 2026).
- **Метод FIFO** по партиям 41.02 — каждая партия имеет реквизит `Партия` (GUID). Партии нужны для понимания «откуда списывался товар» при анализе ОРП.
- ПТУ от ЦБ ЭЛСИ.АЗК → в Комментарии указано «Загружено из торговли» + `ОСЭ_Номер` (идентификатор источника).
- ПТУ из ClearLedger в будущем → в Комментарии будет наш `ИсточникUUID` (для идемпотентности).

## 4. Поток D — Расширение TradeLedger.cfe

Параллельно с типовыми сущностями, в БП ГИГ есть **регистры расширения** для контроля миграции через TL-канал:

| Регистр расширения | Назначение | Что забираем |
|---|---|---|
| `InformationRegister_TL_СоответствиеИсточников` | Маппинг ИсточникUUID → Ref_Key созданного документа | Раз в час — для дашборда «обработано из ClearLedger» |
| `InformationRegister_TL_СверкаПакета` | Сводка по пакетам (kind, station, дата, статус) | Раз в час |
| `InformationRegister_TL_ОшибкиЗагрузки` | Журнал ошибок приёмника | Раз в час (или при ручном обновлении) |
| `Catalog_TL_СтатьиПомощи` | НСИ-справка бухгалтера (можно игнорировать в ClearLedger) | Не забираем |

### Зачем нам это

Когда ClearLedger будет отдавать документы расширению `GIG_Ledger.cfe` для pull в БП, регистр `TL_СоответствиеИсточников` покажет нам обратную связь — какой документ ClearLedger превратился в какой Ref_Key БП. Это замыкает цикл: мы отправили → 1С приняло → мы видим что приняло.

## 8. Контроль качества

При каждой репликации логируем в `SourceSync`:
- Когда тянули
- Сколько забрали по каждой сущности
- Какие ошибки (HTTP 5xx, пустые ответы, невалидный JSON)
- Хеш дельты — чтобы знать что изменилось

Если контрольная сумма документов в закрытом периоде в ClearLedger ≠ контрольной сумме в БП — флаг «эталон расходится» в UI «Точки обслуживания → Период».
