# Представления методики ТП

Используется отдельная локальная PostgreSQL с базой `tp_test`. Сервер проверяет
адрес и имя базы, создаёт только синтетические проект, участников и снимок процесса.
Чтение дорожной карты выполняют реальные роуты и сервисы. Движок Поддержки здесь
не запускается; история процесса задана контролируемой фикстурой.

```bash
TEST_DATABASE_URL=postgresql+asyncpg://...@127.0.0.1:54341/tp_test \
  python e2e/tp-views/server.py
npx vite --config e2e/tp-views/vite.config.ts
TP_VIEWS_ARTIFACTS=/absolute/path node e2e/tp-views/check.cjs
```

Проверяются группы ТП и сбыта, этапы ТУ, замечания, отбор просрочек, переход с
клавиатуры в присоединение, общая сводка, desktop/mobile и обе темы.
Не запускать SQL-тесты одновременно с сервером: фикстура удаляет тестовую схему.
