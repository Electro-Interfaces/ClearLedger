# План корректировки TradeLedger по стандарту управления сложностью

> Результат сплошного аудита приложения против `PROGRESSIVE_DISCLOSURE_CONCEPT.md` (v2.0).
> Это «backlog аудита существующих экранов», которого требует governance-раздел стандарта (§10).
>
> **Дата:** 2026-07-17 · **Охват:** 4 области, ~50 экранов/панелей · **Ветка:** `fuel-edition`
> **Метод:** 4 независимых аудита (Каркас+Фильтр+Виды · Дашборд+Данные+Сверка · Выгрузка+Нормализация · Коннекторы+Настройки+Формы), каждый против пяти правил и чек-листа §А.

---

## 0. Резюме

Аудит вскрыл **два разных класса проблем**, которые нельзя мешать в один список:

- **Класс А — риски корректности данных.** Скрытые критичные значения (НДС-профиль, ключ привязки, порог ТТК, метод себестоимости) и молчаливое массовое применение без предпросмотра. Это не «неудобство» — по логике стандарта (§7) спрятанный сигнал стоит инцидента, и часть находок совпадает с вашими прошлыми P0-багами. **8 находок P0.**
- **Класс Б — UX-долг постепенного раскрытия.** Фрагментация жеста «раскрытие» (5+ реализаций), отсутствие липкости/last-used, «светофорная» палитра, три-четыре несогласованные сущности «сохранённого», фильтр не в URL. **~15 находок P1, ~12 P2.**

**Отдельно — не UX, а функциональная незавершённость, вводящая в заблуждение прямо сейчас** (см. §1). Это стоп-кран, требующий внимания вне зависимости от редизайна.

**Главный вывод по последовательности.** Нельзя начинать с «раскрасить экраны». Правильный порядок: сначала **предохранители корректности** (дёшево, снимают риск сейчас) → потом **фундамент паттернов** (разблокирует всё остальное) → потом раскатка по экранам → полировка.

**Что решить сейчас:** санкционировать **Волну 0** (предохранители, §5) — она малой кровью снимает реальные риски неверных решений оператора и не требует ни редизайна, ни инфраструктуры.

## 3. Фундамент — инфраструктура паттернов (разблокирует всё)

Без этих пяти вещей раскатка по экранам будет копировать разнобой. Строим их **до** массовой раскатки.

| Ф | Что | Опора (уже есть) | Разблокирует |
|---|-----|------------------|--------------|
| Ф1 | **URL-персист `FilterState`** (сериализация в `useSearchParams`) | сейчас только localStorage; в URL — лишь `mode`/`sub` | шаринг выборки ссылкой, deep-link, честное кодирование фильтра в закладки/виды. Главный техриск §11 |
| Ф2 | **Единый `DisclosureSection`** в `components/common` (a11y-контракт: `aria-expanded`, клавиатура, фокус, reduced-motion) | прототип — `CollapsibleSection` из `normalization\AuditTab.tsx` | замена **5+ фрагментированных** реализаций раскрытия одним санкционированным жестом |
| Ф3 | **Единый `ActiveFilterChips`** (удаляемые чипы поверх `FilterState`) | логика чипов — в `common\AdvancedFilters.tsx`; эталон — `FleetFilters` | активные ограничения на виду и удаляемы поштучно во всех фильтрах |
| Ф4 | **Консолидированная сущность `SavedViews`** = навигация(mode/sub) + `FilterState` + параметры + имя + область видимости | сейчас 3–4 сущности: пресеты `FilterContext`, «Недавние», `useViewHistory`, `TabsContext` | понятные «Виды»; шаринг через роль/юрлицо; прозрачность (вид показывает, что кодирует) |
| Ф5 | **Командная палитра `⌘K`** как второй путь ко всему | `CommandDialog` (cmdk) уже есть, не смонтирован; **`⌘K` занят «Инфо»** → переназначить хоткей | fast-path эксперта в обход раскрытий; обнаружимость функций |

**Чистка мёртвого кода (снижает disclosure-debt §7, дешёво):**
- Осиротевшие ветки UI: весь `src\components\dashboard\*` (8 виджетов, не смонтированы) и весь «старый» флоу сверки (`ReconciliationResults` + `MSTOReconciliation*` + `Reconciliation{KPICards,Filters,StationsTable,TransactionsTable,RecommendationsModal,Header,ParamsModal,Summary}`).
- Отдельные орфаны: `layout\GlobalFilters.tsx`, `channels\ChannelScheduleForm.tsx`, `channels\ChannelCard.tsx`, `settings\OneCConnectionForm.tsx` (последний числится в `CLAUDE.md`, но не импортируется).
- Решение по каждому: удалить **или** возродить на общих компонентах §6 с приглушённой палитрой. Оба мёртвых куста используют яркий «светофор».

## 5. Дорожная карта волнами

Порядок продиктован зависимостями: предохранители → фундамент → раскатка → полировка. Сайзинг — грубый T-shirt (уточняется).

### Волна 0 — Предохранители корректности `[сейчас, S–M, без инфраструктуры]`
Снимает реальные риски малой кровью, не требует общих компонентов.
- A1: демо-баннер на `ExportLayerPanel` (как в NormalizationPanel) **или** замена на реальный `BpExportPanel`.
- A2: убрать хардкод «22/122».
- A3: свести расписание к одной честной поверхности («скоро»); убрать декоративный toast.
- P0-1: бейдж `НДС-профиль` на 4 экрана выгрузки.
- P0-2: бейдж активного ключа `[Склад, КодНС]` в коннекторе и маппинге.
- P0-5/A4: гейт-предпросмотр на 6 массовых применений (минимальный: «применить N — подтвердить»).
- P0-6: снять пред-выбор критичных маппингов в авто-сопряжении.
- **Гейт волны:** ни одно тяжёлое действие не мутирует данные без явного предпросмотра; ни одно критичное значение не скрыто.

### Волна 1 — Фундамент паттернов `[M–L]`
- Ф2 `DisclosureSection` + Ф3 `ActiveFilterChips` (вынести из существующих прототипов).
- Ф1 URL-персист `FilterState`.
- Ф4 каркас `SavedViews` (без полной консолидации — модель + адаптеры).
- Чистка мёртвого кода (быстрый P2, снимает шум).
- **Гейт:** общие компоненты готовы и покрыты историей/тестами — раскатка их только использует.

### Волна 2 — Пилот + главный экран `[M]`
- Двухслойный `FilterBar` (§6.3) как эталон: базовое + «Расширенные (N)» + чипы + живой счётчик.
- `DataCategoryPage` (P0-7): двухдорожечный фильтр, чипы, last-used, предпросмотр выгрузки.
- **Гейт:** эталон утверждён DRI; на него равняются остальные.

### Волна 3 — Раскатка по областям `[L]`
- **Нормализация:** пороги/себестоимость на виду (P0-3), предпросмотр bulk (P0-5), приглушить светофор.
- **Выгрузка:** консолидация 4 экранов; предпросмотр пакета; бейджи.
- **Коннекторы:** унификация 5 жестов раскрытия → `DisclosureSection`; разбить «Настройки» на секции; ключ привязки; предпросмотр delete/replace.
- **Сверка:** базис (состав источников) на поверхность (§5); предпросмотр «Применить в L2»; убрать `ENERGY_MOCK_RECON`; шаг к единому конструктору разреза.
- `WorkspaceModeSidebar`: убрать второй уровень гармошки, a11y.
- `OpsCockpit`: drill объекта — в маршрут/drawer вместо модалки-в-модалке.

### Волна 4 — Полировка `[S–M]`
- Палитра-светофор → приглушённая по `CLAUDE.md` (dashboard-виджеты при возрождении, Fleet-бары, старая сверка если сохраняем).
- Обучающие пустые состояния (эталон — `BatchesPage`); демо-строки.
- Липкость/last-used везде (вкладки, фильтры, свёрнутость).
- Ф5 командная палитра `⌘K` (+ переназначить «Инфо»).
- Терминологический дрейф (Коннекторы/каналы/обработки), расхождение маршрутов, `prompt()` в настройках, консолидация 3 поверхностей станций и 2 маппинг-UI.

## 7. Привязка к governance (§10 стандарта)

- Каждая волна проходит **чек-лист §А** поэкранно; экран не мёржится без sign-off DRI.
- Раскрытие/чипы/виды в новых правках — **только через общие компоненты** Ф2–Ф4. Ad-hoc запрещён.
- Экраны, которым нужна плотность (сверка, реестры) — через **исключение** у DRI, не по умолчанию (§7).
- Эта таблица (§4) — живой инвентарь долга; обновляется по мере закрытия.
