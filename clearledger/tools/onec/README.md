# Коннектор к 1С: выгрузка среза компании в пространство

Забирает данные из **файловой базы 1С** (ЭЛСИ.АЗК, Бухгалтерия 3.0) и кладёт их в
нормализованный слой пространства. Запускается **на Windows-машине, где стоит платформа
1С**, — база файловая и локальная, из контейнера её не видно.

Первый заход по компании делают разово из `.dt`; этот набор — то, чем срез **обновляют**
и чем он дополняется. Разовые скрипты в скретчпаде сессии не годятся: через неделю никто
не вспомнит, каким запросом взяты обороты и почему дата уехала на день.

## Порядок

```powershell
# 1. Выгрузить (ТОЛЬКО x86 PowerShell — COM-коннектор 32-битный)
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -ExecutionPolicy Bypass `
  -File q1c.ps1 -QueryDir queries -Base "D:\Users\magsp\1C-Bases\promizol-spb" > pull.out.txt

# 2. Разобрать в нормализованный вид (даты, суммы, виды)
py parse.py            # → pull.json + контрольные суммы

# 3. Собрать загрузчик (данные едут внутри скрипта, сжатыми)
py make-loader.py      # → load-pull.py

# 4. Загрузить в стек и проверить
scp -o ProxyJump=ns1-jump -i ~/.ssh/mag-miran load-pull.py root@10.10.70.53:/tmp/
ssh -J ns1-jump -i ~/.ssh/mag-miran root@10.10.70.53 \
  "docker cp /tmp/load-pull.py office-backend:/app/ && docker exec -w /app office-backend python load-pull.py"
~/.claude/skills/elsy-deploy/scripts/exec-py.sh office verify.py
```

`verify.py` сверяет загруженное с уже выверенным ядром: обороты с аналитикой обязаны
сойтись с проводками по каждому году. Не сошлись — грузить дальше нельзя, разойдутся
витрины.

## Второй набор: реквизиты вида документа (`queries-docs/`)

Шапка документа в слое была беднее самой первички: без назначения платежа, входящего
документа поставщика, счёта организации, статьи ДДС, основания счёта-фактуры и периода
акта сверки. Этот набор их добирает.

```powershell
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -ExecutionPolicy Bypass `
  -File q1c.ps1 -QueryDir queries-docs -Base "<путь к базе>" > enrich.out.txt
py make-enrich.py            # → load-enrich.py (сопоставление + НДС документа из строк)
# затем scp + docker cp + python load-enrich.py, как выше
py fix-sf-vat.py             # НДС полученных счетов-фактур из журнала
py fix-sf-out.py             # НДС выданных: расчётная ставка или документ-основание
py audit-docs.py             # ревизия: что заполнено по видам, где шапка беднее состава
```

**Реквизита «сумма НДС документа» в 1С нет** — он складывается из строк, а у
счёта-фактуры считается по ставке (20/120 у авансовых) либо берётся из документа-основания.
`fix-sf-out.py` в конце сверяется с книгой продаж помесячно: разошлось — значит
сопоставление увело налог не туда, как было с двойником № 1-2212 от 22.12.2023.

**Ключ сопоставления везде — вид + номер + дата + ИНН.** Без ИНН налог одного покупателя
уезжает другому: пара «номер, дата» в 1С не уникальна.

## Что забирается

| Запрос | Что даёт | Куда ложится |
|---|---|---|
| `turnovers` | обороты Дт-Кт с субконто обеих сторон, помесячно | `gl_turnovers` |
| `balances` | сальдо всех счетов с аналитикой на дату среза | `gl_balances` |
| `invoice_payments` | чем и когда закрыт счёт покупателю | `invoice_payments` |
| `vat_invoices` | журнал учёта счетов-фактур (обе части) | `vat_entries` (`issued`/`received`) |
| `vat_claimed` | НДС, предъявленный поставщиком | `vat_entries` (`claimed`) |

Наборы **производные**: загрузчик стирает свой `source` и грузит заново, поэтому
повторный заход не задваивает обороты и не требует совпадения ключей с прошлой выгрузкой.

## Грабли, на которых уже стояли

1. **Субконто в основной таблице регистра через COM недоступно.** `Х.СубконтоДт1` роняет
   выборку целиком («Поле не найдено»). Аналитика берётся ТОЛЬКО из виртуальных таблиц
   (`.ОборотыДтКт(…)`, `.Остатки(…)`), и там она уже свёрнута по месяцу — отсюда и
   отдельная сущность вместо колонок в проводке.
2. **Ссылочные значения печатаются как `<нечитаемо>`.** Оборачивать в `ПРЕДСТАВЛЕНИЕ(…)`,
   иначе приедет тип, а не имя.
3. **Дата: `/Date(ms)/` от эпохи UTC, а время в базе московское.** Без `tz=+3` всё, что
   лежит в 00:00–02:59, уезжает на предыдущий день, а часть проводок — в прошлый месяц.
   Разбор — в `parse.py`, менять только вместе с пересчётом контрольных сумм.
4. **Кириллицу в запросы нельзя писать из bash** — текст запроса лежит отдельным
   UTF-8 файлом в `queries/`, и в самом `.ps1` кириллицы нет.
5. **Файл загрузчика великоват для `exec-py.sh`** (тот шлёт base64 аргументом команды) —
   везти через `scp` + `docker cp`.
6. **Оборотный регистр не имеет `ВидДвижения`** — запрос с этим полем падает.

## Известный пробел

**Сальдо акта сверки** не забрано: `СуммаДокумента` у этого вида нет, а табличная часть
названа не так, как у типовой конфигурации (`ПоДаннымОрганизации` не существует). Имя
искать выгрузкой структуры конфигурации, как метаданные политики. Сам акт при этом
полноценен: контрагент, договор и период сверки на месте.

## Что коннектор пока не забирает

Зарплату (там персональные данные сотрудников клиента — решение МАГа не грузить),
основные средства и НМА, декларации. Товарных остатков в этой базе почти нет: компания
торгует «с колёс», на 41-м счёте одна позиция.
