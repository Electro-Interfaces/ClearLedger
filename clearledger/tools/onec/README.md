# Коннектор к 1С: выгрузка среза компании в пространство

Забирает данные из **файловой базы 1С** (ЭЛСИ.АЗК, Бухгалтерия 3.0) и кладёт их в
нормализованный слой пространства. Запускается **на Windows-машине, где стоит платформа
1С**, — база файловая и локальная, из контейнера её не видно.

Первый заход по компании делают разово из `.dt`; этот набор — то, чем срез **обновляют**
и чем он дополняется. Разовые скрипты в скретчпаде сессии не годятся: через неделю никто
не вспомнит, каким запросом взяты обороты и почему дата уехала на день.

## Порядок

```powershell
# 1. Выгрузить (ТОЛЬКО x86 PowerShell — COM-коннектор 32-битный)
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -ExecutionPolicy Bypass `
  -File q1c.ps1 -QueryDir queries -Base "D:\Users\magsp\1C-Bases\promizol-spb" > pull.out.txt

# 2. Разобрать в нормализованный вид (даты, суммы, виды)
py parse.py            # → pull.json + контрольные суммы

# 3. Собрать загрузчик (данные едут внутри скрипта, сжатыми)
py make-loader.py      # → load-pull.py

# 4. Загрузить в стек и проверить
scp -o ProxyJump=ns1-jump -i ~/.ssh/mag-miran load-pull.py root@10.10.70.53:/tmp/
ssh -J ns1-jump -i ~/.ssh/mag-miran root@10.10.70.53 \
  "docker cp /tmp/load-pull.py office-backend:/app/ && docker exec -w /app office-backend python load-pull.py"
~/.claude/skills/elsy-deploy/scripts/exec-py.sh office verify.py
```

`verify.py` сверяет загруженное с уже выверенным ядром: обороты с аналитикой обязаны
сойтись с проводками по каждому году. Не сошлись — грузить дальше нельзя, разойдутся
витрины.

## Второй набор: реквизиты вида документа (`queries-docs/`)

Шапка документа в слое была беднее самой первички: без назначения платежа, входящего
документа поставщика, счёта организации, статьи ДДС, основания счёта-фактуры и периода
акта сверки. Этот набор их добирает.

```powershell
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -ExecutionPolicy Bypass `
  -File q1c.ps1 -QueryDir queries-docs -Base "<путь к базе>" > enrich.out.txt
py make-enrich.py            # → load-enrich.py (сопоставление + НДС документа из строк)
# затем scp + docker cp + python load-enrich.py, как выше
py fix-sf-vat.py             # НДС полученных счетов-фактур из журнала
py fix-sf-out.py             # НДС выданных: расчётная ставка или документ-основание
py audit-docs.py             # ревизия: что заполнено по видам, где шапка беднее состава
```

**Реквизита «сумма НДС документа» в 1С нет** — он складывается из строк, а у
счёта-фактуры считается по ставке (20/120 у авансовых) либо берётся из документа-основания.
`fix-sf-out.py` в конце сверяется с книгой продаж помесячно: разошлось — значит
сопоставление увело налог не туда, как было с двойником № 1-2212 от 22.12.2023.

**Ключ сопоставления везде — вид + номер + дата + ИНН.** Без ИНН налог одного покупателя
уезжает другому: пара «номер, дата» в 1С не уникальна.

## Что забирается

| Запрос | Что даёт | Куда ложится |
|---|---|---|
| `turnovers` | обороты Дт-Кт с субконто обеих сторон, помесячно | `gl_turnovers` |
| `balances` | сальдо всех счетов с аналитикой на дату среза | `gl_balances` |
| `invoice_payments` | чем и когда закрыт счёт покупателю | `invoice_payments` |
| `vat_invoices` | журнал учёта счетов-фактур (обе части) | `vat_entries` (`issued`/`received`) |
| `vat_claimed` | НДС, предъявленный поставщиком | `vat_entries` (`claimed`) |

Наборы **производные**: загрузчик стирает свой `source` и грузит заново, поэтому
повторный заход не задваивает обороты и не требует совпадения ключей с прошлой выгрузкой.

## Грабли, на которых уже стояли

1. **Субконто в основной таблице регистра через COM недоступно.** `Х.СубконтоДт1` роняет
   выборку целиком («Поле не найдено»). Аналитика берётся ТОЛЬКО из виртуальных таблиц
   (`.ОборотыДтКт(…)`, `.Остатки(…)`), и там она уже свёрнута по месяцу — отсюда и
   отдельная сущность вместо колонок в проводке.
2. **Ссылочные значения печатаются как `<нечитаемо>`.** Оборачивать в `ПРЕДСТАВЛЕНИЕ(…)`,
   иначе приедет тип, а не имя.
3. **Дата: `/Date(ms)/` от эпохи UTC, а время в базе московское.** Без `tz=+3` всё, что
   лежит в 00:00–02:59, уезжает на предыдущий день, а часть проводок — в прошлый месяц.
   Разбор — в `parse.py`, менять только вместе с пересчётом контрольных сумм.
4. **Кириллицу в запросы нельзя писать из bash** — текст запроса лежит отдельным
   UTF-8 файлом в `queries/`, и в самом `.ps1` кириллицы нет.
5. **Файл загрузчика великоват для `exec-py.sh`** (тот шлёт base64 аргументом команды) —
   везти через `scp` + `docker cp`.
6. **Оборотный регистр не имеет `ВидДвижения`** — запрос с этим полем падает.

## Третий набор: зарплата (`queries-payroll/`)

Грузится полностью по решению МАГа 13.08.2026 — и, как всё остальное, **сначала в слой**:
документы встают в общий реестр видами `payroll_accrual` и `payroll_payment` (участок
«Зарплата»), сотрудники — в `employees`, расчёт — в `payroll_entries` (`accrual`,
`deduction`, `ndfl`, `contribution`, `payment`).

```powershell
C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -ExecutionPolicy Bypass `
  -File q1c.ps1 -QueryDir queries-payroll -Base "<путь>" > zpull.out.txt
py make-payroll.py          # → load-payroll.py
# scp + docker cp + python load-payroll.py
POST /api/books/relink      # проводки зарплаты садятся на свои документы
py verify-payroll.py        # сверка с регистром
```

⚠ **ПДн.** Набор несёт ФИО, ИНН, СНИЛС и даты рождения физических лиц. Доступ к
`employees` и `payroll_entries` обязан быть уже, чем к остальному слою.

### Что здесь особенного

1. **Аванс (первая половина месяца) проводок НЕ делает.** На пилоте 17 таких документов
   на 340 000 ₽ начислений, 44 200 ₽ НДФЛ и 11 402,60 ₽ взносов. Без пометки это читается
   как расхождение слоя с регистром; документ помечен в реквизитах («Расчёт: аванс за
   первую половину месяца»), а `verify-payroll.py` считает итог отдельно от аванса.
   После этого сходится точно: итоговые начисления 760 000 ₽ = оборот Кт 70.
2. **Шапка ведомости на выплату не читается запросом вовсе** — падает на любом поле,
   даже на одном номере, хотя её табличная часть читается. Реквизиты шапки берём через
   `Т.Ссылка.<Реквизит>` из табличной части (`payment.txt`).
3. **Взносы лежат колонками по фондам** в одной строке (ПФР, ФФОМС, ФСС, травматизм) —
   разворачиваем в отдельные записи, иначе «сколько ушло в ФСС» отвечается чтением колонок.
4. **`meta-find.ps1`** — поиск объектов конфигурации по имени с их составом (реквизиты,
   табличные части, измерения и ресурсы). Им и найдены имена всего блока: гадать по
   названиям бесполезно, несуществующее поле роняет запрос целиком.

## Волна 2 (`queries-docs/status.txt`, `sf-vat.txt`, `bank-split.txt`, `bank-head.txt`, `act-*.txt`)

Разбор и применение — `make-wave2.py`. Что здесь важно знать:

- **Признак «Проведён» и пометку удаления надо выбирать явно.** Колонка `status_1c`
  имеет значение по умолчанию «Проведён», и пока признак не выбирали, все 3256
  документов выглядели проведёнными — включая 485 регламентных операций, которые в 1С
  не проведены. На этом признаке считается готовность периода.
- **У счетов-фактур ЕСТЬ `СуммаНДСДокумента`** (у реализации, поступления и счетов —
  нет). Считать их налог ставкой или по документу-основанию не нужно: эвристика
  завышала налог у двух документов.
- **«Расшифровка платежа»** — табличная часть банковских документов: НДС, договор,
  статья ДДС и ссылка на счёт. Без неё платёж в слое — одна сумма без аналитики.
- **Акт сверки читается полностью:** `ОстатокНаНачало`, `…ПоДаннымКонтрагента`,
  `ЕстьРасхождения` и ТЧ `ПоДаннымОрганизации` (Дебет, Кредит, Документ). Сальдо на
  конец = остаток на начало + дебет − кредит.
- **Пустая дата 1С приезжает годом 0100, а не отрицательным timestamp.** Отбрасывать
  по году (`dt.year < 1900`), иначе теряются даты рождения до 1970 года.

## Грабли выгрузки (август 2026)

- **Сортировка по псевдониму `ПРЕДСТАВЛЕНИЕ(...)` роняет запрос целиком** с сообщением
  «Ссылка на объект не указывает на экземпляр объекта». `УПОРЯДОЧИТЬ ПО` — только по
  полю таблицы (`Т.Дата`), не по вычисленному имени колонки.
- То же сообщение приходит, **если поля нет у объекта**. У `Документ.РегламентированныйОтчет`
  нет реквизита `Номер` — из-за него падал весь запрос. Ищите поле перебором по одному:
  `meta-find.ps1` печатает не всё.
- **Связь документа с договором есть почти у всей первички** (2331 из 2642 у пилота),
  включая счета-фактуры. Забирать её надо отдельным срезом «вид + номер + дата + ИНН →
  договор»: в шапке документа при обычной выгрузке она теряется.
- **Реквизиты книг покупок и продаж** живут в `РегистрНакопления.НДСЗаписиКнигиПокупок`
  и `...Продаж`, а не в журнале счетов-фактур. Без них не собрать декларацию: событие,
  код вида операции, документ оплаты, дополнительный лист, корректируемый период.
  Контроль загрузки: сумма НДС книги = оборот счёта 68.02 (у пилота сошлось до копейки).
- **Уведомления об исчисленных суммах** без табличной части `Налоги` — пустые оболочки:
  ни суммы, ни КБК, ни срока уплаты.
- **`gl_references.code` и `contracts.date` объявлены NOT NULL** — пустое значение кладите
  строкой `''`, а не `NULL`.
- **`exec-py.sh` не видит файлы, положенные в контейнер через `docker cp`**: скрипт
  запускается в новом контейнере. Большие наборы грузите SQL-файлом через
  `docker exec -i <db> psql < файл.sql`.

## Организация — обязательное поле каждого запроса

Компания пространства это КЛИЕНТ (одна база 1С), организация — ЮРЛИЦО внутри его
учёта. У аутсорсера в одной базе обычно ООО и ИП одного владельца, и без разреза их
НДС и прибыль складываются в одну цифру — тихо, без ошибки на экране.

**Каждый новый запрос обязан тащить `ПРЕДСТАВЛЕНИЕ(<алиас>.Организация) КАК Организация1С`**,
а загрузчик — резолвить её в `organization_id` по имени или ИНН.

Где организации нет и не будет: `Контрагенты`, `Номенклатура`, `Сотрудники`,
`ФизическиеЛица`, `Организации`, `ЗадачиБухгалтера` — это общие справочники клиента.

Три грабли:
- **У табличной части своей организации нет** — только `Т.Ссылка.Организация`.
  Иначе COM падает с «Object reference not set to an instance of an object».
- **`meta-find.ps1` не печатает измерения регистра бухгалтерии**: у
  `РегистрБухгалтерии.Хозрасчетный` и его виртуальных таблиц (`ОборотыДтКт`,
  `Остатки`, `ОстаткиИОбороты`) организация ЕСТЬ, хотя в дампе её не видно.
- **В запросе с `ОБЪЕДИНИТЬ ВСЕ` поле нужно во ВСЕХ частях**: добавив его в одну,
  получаешь разное число колонок и падение всего запроса.
