# Общая запись эксплуатационных файлов

`ops_terms.store_file` использует `file_store.put_and_flush`, сохраняя прежние
UUID, filename fallback, MIME, SHA-256 и `purpose=data`. Остальные потребители
`file_store.put` сохраняют прежний нефлаширующий контракт и `purpose=attachment`.
Commit остаётся у прикладного сценария.

Путь строится по серверному UUID. Создание exclusive: совпадение ID не
перезаписывает существующие bytes. Ошибка записи/add/flush или отмена flush
удаляет только новый файл; ошибка cleanup логируется без пути и содержимого.
Предварительный ID допускается только как внутренний UUID, не строка клиента.

Проверено локально на синтетике: 9 файловых тестов (настоящие tmpfiles),
177 regression тестов документов, архива, ACL, эксплуатационных периодов и
оборудования. Два прежних SQLAlchemy warning об archive DELETE остаются.

Это часть M07. Общий cleanup при более позднем rollback транзакции,
оставшиеся прямые writers и синхронизация с объектным хранилищем ещё требуют
отдельного изменения; текущий helper не обещает атомарность диска и БД.
Выпуск на рабочем пространстве не выполнялся.
