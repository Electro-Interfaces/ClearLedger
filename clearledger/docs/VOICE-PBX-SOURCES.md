# Общая АТС и источники звонков

Раздел `/voice/pbx` показывает звонки выбранного источника:
`node` (наш узел), `mango` или `megafon`. В меню он называется «АТС».
Основной источник node читает **прямой API узла** `/voice/api/v1/calls`: входящие,
ожидание, разговоры и завершённые звонки. Он не ждёт итогового вебхука в Поддержку.
Журнал обновляется каждые две секунды, показывает текущую фазу и не дублирует
строку при переходе к завершённому звонку. История API провайдеров — отдельные
варианты выбора, явно подписанные как история API.
Подключения API провайдеров настраиваются в `/voice/connections` через штатный SSO
в Поддержку. Голосовой SIP-транк и API истории — отдельные подключения.
Работающий SIP-транк Mango не означает, что загружена история API Mango.

Основной журнал `/voice/calls`, статистика и месячный отчёт используют тот же выбор
источника. Для узла сохраняются его расширенные экраны, записи, показатели и доступ
через API узла; для провайдеров открываются история, операторы, группы и выгрузки.
При наличии подключения собственного узла он выбирается по умолчанию. Ссылки с
метриками, идентификаторами и участниками узла сохраняют свой источник.

## Контракт

- `GET /api/voice/pbx/sources`: доступные типы источников, безопасные состояния
  подключений и `default_source`. Без credentials, config и адресов внешних систем.
- `GET /api/voice/pbx?source=node|mango|megafon`: период, фильтры, сводка и страницы
  завершённых звонков выбранного источника из Поддержки. Вариант node этого
  архивного API оставлен для совместимости; основной экран и живой журнал его
  не используют. Если источник не указан — node.
- `GET /api/voice/pbx/calls/{id}?source=…`: карточка только того же источника и компании.
- Старые API `/api/voice/megafon` и `/api/voice/megafon/calls/{id}` сохраняются;
  без явного `source` они читают МегаФон. Старый маршрут страницы также поддержан.

В каждом запросе проверяются пользователь, членство в компании, подключённое
приложение «Телефония», роль администратора и точная карта компании Поддержки.
`X-Company-Id` и все параметры входят в ключи React Query. Смена источника сбрасывает
карточку и несовместимые фильтры; смена компании не показывает прежние данные.

Журнал узла в Поддержке — `asterisk_node`; Mango — `mango`/`mango_api`;
МегаФон — `megafon`/`megafon_api`. Эти выборки не складываются: один физический
разговор может присутствовать и в журнале узла, и в детализации провайдера.
Ссылка на запись и секретные поля провайдера в ответы истории не включаются.

## Чтение базы и диагностика

В объединённой базе пространства Ядру нужно чтение трёх таблиц Поддержки:
`public.call_records`, `public.connectors`, `public.cc_agent_identities`.
Перед чтением отдельно проверяются наличие таблиц, права SELECT и версия схемы.
Отсутствие прав больше не выдаётся за отсутствующую миграцию.
Узкое идемпотентное восстановление grants закреплено в поставке пространства;
права записи и остальные таблицы оно не затрагивает.

## Проверки

`tests/test_megafon_voice.py` проверяет старые и общие API: фильтры, пагинацию,
аудит, компании, разделение трёх источников, карточки, права и ошибку готовности.
Запускать только с отдельной `TEST_DATABASE_URL` по правилам tests/conftest.py.

`node e2e/megafon-voice.check.mjs` проверяет интерфейс на синтетических данных:
старые ссылки, источники, фильтры и сброс, карточки, смену компании, состояния,
CSV/Excel/печать, выбор провайдера в подключениях, desktop и mobile.
Нужен установленный Playwright; результаты сохраняются вне исходников.
