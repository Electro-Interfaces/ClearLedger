# Управляющее пространство: backend V1

Обзор читает чаты, задачи и встречи из изолированных пространств. Общая база,
копирование OAuth-токенов, запись содержимого в кеш и мутации не используются.
Поставка выключена по умолчанию. Этот документ описывает код, а не выполненную
настройку или выпуск: в production работа не проводилась.

## HTTP

`GET /api/management/status` возвращает `{ "enabled": boolean }`. Нужны обычный
Bearer Ядра и **обязательный** `X-Company-Id`; членство проверяется даже при
выключенном обзоре. Нет запросов к удалённым источникам и выдачи их каталога.
Меню показывается только при `enabled=true`; ошибка конфигурации даёт 503.

`GET /api/management/overview` использует такую же авторизацию и заголовок.

| Параметр | Значение |
|---|---|
| `kind` | Обязательный: `chats`, `tasks`, `calendar` |
| `space` | `all` по умолчанию либо разрешённый код источника |
| `query` | Буквальный поиск по заголовку без учёта регистра, максимум 200 Unicode code points |
| `limit` | По умолчанию 100, диапазон 1–200; общий предел результата |
| `date_from`, `date_to` | Для календаря обязательны, `YYYY-MM-DD`, обе даты включительно |
| `time_zone` | IANA, по умолчанию `Europe/Moscow` |

Календарный период: `[начало date_from, начало дня после date_to)` в `time_zone`,
далее перевод в UTC. Учитываются смена UTC-смещения и пересечение встречи с окном;
максимум 367 календарных дней. Неверный период/пояс даёт 422. Источник получает
исходные даты и тот же пояс, поэтому повторно интерпретировать UTC как местный
день нельзя. Непредставимые UTC-границы (например, начало 0001-01-01 в
Europe/Moscow или день после 9999-12-31) отклоняются с публичным 422.
Произвольной нижней границы по году нет.

```json
{
  "enabled": true,
  "fetched_at": "2026-10-24T12:00:00Z",
  "items": [],
  "sources": [
    {"code": "desk", "name": "Элси", "state": "ok",
     "fetched_at": "2026-10-24T12:00:00Z", "error": null, "truncated": false}
  ],
  "truncated": false
}
```

Поля item: `id`, `source_id`, `kind`, `source`, `title`, `href`; необязательные
`subtitle`, `status`, `updated_at`, `author_name`, `assignee_name`, `due_at`,
`starts_at`, `ends_at`, `unread_count`, `project_name` сериализуются также как null.
`source` содержит `code`, `name`, `company_id`, `company_name`.
`id = code:company_id:kind:source_id`. Идентификаторы исходных объектов — UUID.

Локальная компания берётся из проверенного заголовка, название из её карточки;
удалённая идентичность и компания — только из доверенной конфигурации.
Входящие удалённые `href`, `source`, `id` игнорируются. Backend формирует ссылки:

* чат: `/?company=<uuid>&chat=<uuid>`;
* задача: `/docs/work?company=<uuid>&view=errands&task=<uuid>`;
* встреча: `/docs/work?company=<uuid>&view=calendar&event=<uuid>`.

Для удалённых ссылок добавляется только разрешённый HTTPS origin источника.
UI должен обработать `company` через существующий выбор компании, `chat` через
панель чата; реальная карточка заново проверяет права своей обычной авторизацией.
Scoped токен в URL/браузер не передаётся. Если в браузере нет сессии источника,
потребуется обычный вход в него.

Задачи сортируются по `updated_at` убыванию, встречи по `starts_at` возрастанию;
чаты без метки доступной активности — по составному id. После слияния применяется
общий `limit`; `truncated=true` при усечении любого источника или общего списка.
Поиск применяется до ограничения. `%`, `_` и обратная косая черта ищутся буквально
во всех трёх видах данных; пользовательский SQL-шаблон не поддерживается.
Пагинации/cursor в V1 нет.

`sources.state`: `ok`, `error`, `forbidden`, `not_configured`. Отказ одного
источника оставляет данные остальных. Ошибки содержат только публичные сообщения,
без hostname, ответа upstream, пути конфигурации или ключа. Успешный источник
сообщает время своего чтения; при ошибке `fetched_at=null`, старые данные не
возвращаются. Источник **без grant для actor/company/kind отсутствует целиком**,
в том числе в статусах и счётчиках; запрос его кода возвращает 404.
На всех трёх management GET установлен `Cache-Control: no-store`, включая
штатные ошибки авторизации, зависимостей, валидации и конфигурации. Политика
задаётся на общем классе маршрута и сохраняет стандартные HTTP-тела и статусы.

UI объясняет предел поиска и календарного периода до отправки некорректного
запроса. HTTP 404 показывает нейтральную недоступность источника или раздела
и предлагает сбросить отбор; этот статус не доказывает несовместимость версии.
HTTP 422 предлагает изменить условия, без повтора того же запроса. Тела
серверных ошибок в интерфейс и toast не передаются.

## Видимость на стороне источника

`management_local.read_local` переиспользует действующие функции:

* членство и скоуп компании: `auth.assert_company_member`;
* доступ к продукту: `assert_company_product`, `_assert_work` из tasks-router;
  наличие включённого приложения: `app_registry.company_apps`;
* задачи: `_visible_to`, `_is_admin`, `_not_personal`; сохраняются author,
  assignee, watcher, participant и административные права исходного движка;
* встречи: `_my_events_clause` из work-router плюс встречи с `visibility=company`,
  то есть объединение исходных «Мой» и «Общий» календарей;
* чаты: обязательное участие, `chat_scope_of` и `_assert_participant` из chat-router.

Продукт `chat` должен быть включён и разрешён человеку. Для работы нужен `docs`
либо прежний `plan` по исходному ACL. При явном выключении `docs` обзор не
обходит запрет через `plan`. Чаты задач/заявок, архив и комнаты других компаний
не подмешиваются в общий список. Суперадминистратор в обзоре чатов тоже видит
только комнаты со своим участием.

Личные записи задач в общий реестр не входят, в том числе собственные;
чужие `private` остаются закрытыми по действующему ACL, собственная роль
администратора сохраняется. Встречи и сроки задач — разные сущности: календарь
не создаёт «встреч» из `Task.due_at`.

В V1 у чатов выдаются название и тип; текст сообщений, история, unread и время
последнего сообщения не запрашиваются. Так обзор не раскрывает сообщения до
`ChatParticipant.history_from`. Не вызываются `ensure_company_rooms`, операции
создания членства, пометки прочитанным или аудит чужого разговора.
Обычная авторизация Ядра может обновить presence текущего пользователя своим
существующим механизмом; сам обзор не делает commit и не изменяет контент.

## Конфигурация

Процессу backend передать **экспортированную переменную окружения**
`MANAGEMENT_CONFIG_PATH=/run/management/config.json`. Не добавлять её как
неизвестное поле в `.env`, читаемый основным `Settings`. JSON хранить вне git,
права файла 0600, readonly mount каталога. Код читает файл на каждом запросе,
поэтому атомарная замена файла в смонтированном каталоге отзывает grants без
перезапуска. Некорректный/недоступный файл даёт 503 и не включает fallback.
Отсутствующая переменная — штатное выключенное состояние.

Локальный обзор без удалённых подключений:

```json
{"enabled": true, "hub_enabled": true, "code": "desk", "name": "Элси"}
```

`enabled` разрешает механизм целиком, `hub_enabled` разрешает управляющий экран и
агрегацию. Оба флага по умолчанию false. Принимающий источник обычно использует
`enabled=true, hub_enabled=false`: inbound grants не включают его собственный
управляющий режим. Коды пространства — уникальные строчные латинские
буквы/цифры/`_`/`-`, начиная с буквы, до 40 символов; `all` зарезервирован UI.

Пример управляющего backend; UUID вымышленные, значения ключей намеренно отсутствуют:

```json
{
  "enabled": true,
  "hub_enabled": true,
  "code": "desk",
  "name": "Элси",
  "signing_private_key_b64": "BASE64_PKCS8_PRIVATE_PEM",
  "sources": [{
    "code": "customer",
    "name": "Клиентское пространство",
    "base_url": "https://customer.example.invalid",
    "company_id": "22222222-2222-4222-8222-222222222222",
    "company_name": "Компания клиента",
    "grants": [{
      "id": "reader-one",
      "local_user_id": "11111111-1111-4111-8111-111111111111",
      "local_company_id": "33333333-3333-4333-8333-333333333333",
      "remote_user_id": "44444444-4444-4444-8444-444444444444",
      "kinds": ["chats", "tasks", "calendar"]
    }]
  }]
}
```

На backend источника:

```json
{
  "enabled": true,
  "hub_enabled": false,
  "code": "customer",
  "name": "Клиентское пространство",
  "trusted_issuers": [{
    "issuer": "desk",
    "public_key_b64": "BASE64_PUBLIC_PEM",
    "grants": [{
      "id": "reader-one",
      "actor_user_id": "11111111-1111-4111-8111-111111111111",
      "actor_company_id": "33333333-3333-4333-8333-333333333333",
      "user_id": "44444444-4444-4444-8444-444444444444",
      "company_id": "22222222-2222-4222-8222-222222222222",
      "kinds": ["chats", "tasks", "calendar"]
    }]
  }]
}
```

Сгенерировать отдельный RSA ключ не менее 2048 бит, например `openssl genpkey
-algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out management-private.pem`, затем
`openssl pkey -in management-private.pem -pubout -out management-public.pem`.
В соответствующие поля JSON положить base64 всего PEM (`base64 -w0 <файл>`).
Приватный ключ остаётся только в управляющем backend; источник получает публичный
ключ через доверенную конфигурацию. Не использовать JWT_SECRET, пользовательский
токен или ключ с правами администратора. Встроенные PyJWT/cryptography/httpx уже
в зависимостях; новые зависимости не добавлены.

У каждого источника один `company_id`; максимум 20 источников. `base_url` —
HTTPS origin без userinfo, пути, query, fragment. Редиректы, cookies, proxy env
и автоматическое получение JWKS отключены. Администратор конфигурации явно
разрешает этот адрес; не принимать его из запроса пользователя.

## Межсерверный протокол

Управляющий backend вызывает `GET /api/management/source-overview` с фильтрами
и своим короткоживущим Bearer. Обычный токен Ядра на этой ручке не принимается.
Ответ: `{fetched_at, items: ManagementRecord[], truncated}`; запись содержит только
поля item без `source`, `href`, составного `id`. В ответе нет списка иных источников.
Receiver не вызывает последующие источники: цепочное делегирование отсутствует.

JWT: только RS256, `typ=management+jwt`, `scope=management:read`, `iss=<hub code>`,
`aud=management:<source code>`, `sub=<actor UUID>`, `actor_company_id`,
`target_user_id`, `target_company_id`, `grant_id`, конкретный `kind`, `iat`, `nbf`,
`exp`, случайный `jti`. TTL ровно 60 секунд при выдаче и не более 60 при проверке;
`nbf=iat`, подпись, аудитория, issuer, срок и все привязки обязательны.
Публичный ключ выбирается только из pinned allowlist issuer. Email не участвует
в сопоставлении, вход не создаёт пользователей и членства. Grants нужны **на обеих
сторонах** с совпадающими UUID/id/kind.

Источник при каждом запросе заново проверяет grant, существование пользователя,
отсутствие `mail_only`/служебной учётки, явное членство даже для superadmin и
исходные product/visibility ACL. В текущей модели User нет `is_active`:
отзыв доступа выполняется удалением grant/членства либо закрытием обычного входа
через `mail_only`. Удалённый заголовок `X-Company-Id` не меняет компанию JWT.
Scoped credential не принимается обычными ручками Ядра. Сессии инженера по пропуску
могут читать локальный обзор в своём скоупе, но удалённые grants не активируют.

Токен не одноразовый: в течение 60 секунд возможен повтор **того же ограниченного
чтения**. Persistent replay/cache хранилищ нет. Скомпрометированный приватный ключ
позволяет действовать только в пределах разрешённых принимающей стороной grants;
для отзыва удалить соответствующий issuer/grant или заменить ключи на обеих сторонах.

Каждый HTTP-вызов ограничен 8 секундами суммарно и 6 секундами на сетевую операцию,
ответ ограничен 2 МБ и 200 записями; ответ
неверного kind/UUID/количества или с дубликатами отклоняется целиком. Ошибка
отдельного источника не ослабляет авторизацию и не включает гостевой/admin fallback.

## Проверка и запуск

Запуск backend штатный: из `clearledger/server` — `uvicorn app.main:app`, с обычными
переменными окружения проекта и экспортированным `MANAGEMENT_CONFIG_PATH`.
Схема/миграция или общий сервис данных для обзора не нужны. Проверочный запрос:

```bash
curl --fail --get "$CORE_BASE_URL/api/management/overview" \
  -H "Authorization: Bearer $CORE_ACCESS_TOKEN" -H "X-Company-Id: $CORE_COMPANY_ID" \
  --data-urlencode kind=calendar --data-urlencode date_from=2026-10-24 \
  --data-urlencode date_to=2026-10-24 --data-urlencode time_zone=Europe/Moscow
```

Offline unit без обращения к БД: `python -m pytest tests/test_management_unit.py -q`.
Интеграционные тесты: `TEST_DATABASE_URL=<отдельная тестовая PostgreSQL> python -m
pytest tests/test_management_api.py -q`. Общий conftest удаляет схемы: URL рабочей
базы здесь запрещён. Для этой задачи координатор выделил отдельный контейнер
`elsy-control-test-db-20261024`, база `clearledger_test`; секретный URL не сохранялся
в git. Проверены негативные JWT/grant сценарии, read-only chat, tenant/product ACL,
личные/закрытые записи, календарный день и DST, частичный отказ, усечение, доверенные
ссылки и отказ по ошибочной конфигурации.

V1 не обещает push real-time. UI может обновлять обзор вручную/опросом. Реальные
межпространственные сети/ключи не настраивались; HTTP-отказы и проекции проверены
offline transport, источник и его ACL — через ASGI на отдельной PostgreSQL.

## Выпуск поверх текущих пространств,25.10.2026

Frontend накладывается на доказанный живой baseline234922cd (desk1.2.739).
Каждый backend собирается отдельным производным образом от своего immutable
живого ImageID; исходные auth/models/seed/предметные сервисы и зависимости
сохраняются. В main.py добавляется только регистрация нового роутера.

`RemoteSource.receiver_code` — необязательный код физического receiver. Если он
не задан, JWT aud остаётся `management:<source.code>`. При явном поле точная
аудитория берётся из receiver_code, а source.code остаётся уникальным алиасом
компании в UI и составном id. Это позволяет трём явно разрешённым компаниям
Аудита использовать один receiver=office. Все UUID/grant/kind проверки сохранены;
wildcard audience и автоматического сопоставления людей нет.

Для старого runtime чат использует его существующий chat_router._chat_scope;
обязательное участие и исходный _assert_participant сохраняются. Схемы и
зависимости ради обзора не меняются. Фактические версии и приёмка выпуска
фиксируются отдельно в частном ecosystem-deploy, без рабочих ключей в Git.

Для источника с неподтверждённой поддержкой переходов можно явно задать
`original_links_enabled=false` (по умолчанию true). Данные и их ACL остаются
доступны, но href пуст; UI показывает «Ссылка на оригинал недоступна». Это
явное ограничение совместимости старого frontend, а не успешная приёмка
перехода. После отдельного обновления frontend флаг можно вернуть без рестарта.
