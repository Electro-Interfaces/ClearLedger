# Корпоратив (ЮЛ) — блупринт рабочего пространства ЭЗС

> Проработка структуры табов пункта «Корпоратив» (energy-профиль, РусГидро).
> Черновик для согласования — от 2026-07-04. Обновлять по мере реализации.

## Назначение
Клиент-центричное пространство для управления **корпоративным направлением** ЭЗС:
постоплата по договору, договорные тарифы (матрица/плоский/розница). Отличается от
общих табов «Сессии» (разрезы станция/коннектор/время с тумблером ЮЛ) — фокус на
**клиентах, договорах, тарифах, рентабельности и биллинге**, чего общие табы не дают.

## Что уже есть в данных (L2)
Каждая ЮЛ-сессия несёт две пары цена/выручка:
- **розница станции** — `tariff` / `amount` (у ЮЛ amount=0, постоплата);
- **договор ЮЛ** — `client_tariff` / `client_amount` (= energy × договорной тариф).
Плюс `client_name` (джойн по телефону). Выгрузка построчно — `GET /charge-sessions/export`.

## ⚠️ Фундамент: реестр клиентов
Для клиент-центричных табов нужно **сохранять реестр** `corporate_clients` при загрузке
справочника (сейчас договорные атрибуты живут только в xlsx, на сессии оседает лишь
имя+тариф). Поля: `name`, `phone`(ключ=user_id), `mode` (matrix/flat/retail), `rate`,
матрица (регион×коннектор), `contract_start`, `status`, `users`, `inn?`. Сессия ↔ клиент
по `client_name`/телефону. Это открывает Клиентов / Тарифы / Договоры.

## Табы

### 1. Обзор
KPI-полоса ЮЛ: **Договорная выручка · Энергия · Сессии · Активных клиентов · Ср.тариф ЮЛ
· Скидка к рознице (₽ и %)**. Виджеты: топ-5 клиентов по выручке (гориз.bar); доля ЮЛ в
сети (выручка/энергия/сессии); мини-тренд корп-выручки; **алерт-строка** (клиенты с
сессиями, но без тарифа; договоры не «Действующая»; клиенты с глубокой скидкой).

### 2. Клиенты (реестр + карточка)
Главная рабочая таблица по организациям: `Клиент · Договор (дата/статус/юзеры) · Сессии
· Энергия · Договорная выручка · Эфф.тариф ₽/кВтч · Розница-эквивалент · Скидка/наценка
₽ и % · Режим тарифа`. Сортировка + data-bars. Клик → **карточка клиента**: его KPI +
разрезы (станции/коннекторы/время/динамика) + выгрузка сессий клиента
(`/charge-sessions/export?client=`).

### 3. Тарифы и договоры
Модель цен по клиенту: `Режим · Ставка (flat) · Матрица регион×коннектор (matrix) ·
Эфф.тариф факт vs номинал`. Ревизия условий: клиенты без тарифа, договоры истекают/на
паузе. **Roadmap:** правка тарифов из UI → перезапись матрицы/ставки → пересчёт
`client_amount` (переобогащение).

### 4. Рентабельность + Биллинг
- **Розница vs Договор** (гэп-анализ): по клиенту розница-эквивалент (energy×tariff) vs
  договорная выручка, разница ₽/% — скидка/наценка. Итог по направлению: сколько сети
  «стоят» корп-скидки (напр. МЦБС −47к по 12₽; Каршеринг +80к).
- **К выставлению (биллинг)**: за период по каждому клиенту сумма к счёту (= договорная
  выручка), энергия, сессии; **реестр к выставлению + выгрузка xlsx**. Операционный выход
  постоплаты.

### 5. (опц.) Динамика
Тренд договорной выручки/энергии ЮЛ по месяцам и по топ-клиентам; привлечение (новые
клиенты по дате договора). Частично покрывается общим табом «Динамика» с фильтром ЮЛ.

## Порядок реализации
0. **corporate_clients** — persist реестра при загрузке справочника (фундамент).
1. **Обзор + Клиенты** (реестр + карточка) — рабочее ядро.
2. **Рентабельность + Биллинг** — операционный выход (данные уже есть).
3. **Тарифы и договоры** — управление условиями.
4. **Динамика** — опционально.
