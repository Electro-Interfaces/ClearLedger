# Вход синхронизации справочников 1С

Статус: исходники подготовлены; совместная проверка ожидается. Импорты,
сбор тестов и runtime не выполнялись. Выпуск и охват всех писателей открыты.

`OneCSyncService.sync_catalogs(connection)` получает один полный план
Company S + RefComposite X до `_start_log`, его flush и записей справочников.
Раньше второй SELECT организаций мог вызвать autoflush первого UPDATE до
барьера контрагентов. В сочетании с порядком native Ref S → CP → договор →
Organization SHARE это давало потенциальный обратный порядок. Это вывод по
исходникам, а не сообщение о наблюдавшемся взаимном ожидании.

Сессия с pending new/dirty/deleted отклоняется без flush и потери изменений.
Идентификатор подключения берётся из ORM identity сохранённого объекта;
компания читается скалярным запросом из БД до плана и после ожидания.
Перенос подключения в незапланированную компанию отклоняется. После B
блокируются строки Company и OneCConnection в режиме SHARE; подключение
перечитывается в сессию команды. Сохранённый объект из другой сессии допустим.
Чистые retained Organization/Counterparty/Contract истекают один раз до
первой записи. Проверки capability сохраняют привязку к сессии, корню и
соединению вокруг этапов синхронизации.

Публичная сигнатура, HTTP-политика, порядок справочников и обработка обычных
ошибок сохранены. Сервис не делает commit/rollback: HTTP завершает `get_db`,
программный caller завершает свою транзакцию. Блокировки остаются на время
внешнего обмена. Отказ входа происходит до создания лога. Ранее выполненные
и уже сброшенные SQL нельзя обнаружить по чистоте identity map: caller обязан
входить до записей и блокировок. Найдены два HTTP-входа и один smoke caller с
предварительным commit; динамические вызовы неизвестны. Свежесть ACL после
ожидания этим изменением не заявляется.

Два новых тестовых модуля имеют статус AUTHORED/NOTRUN. PG-сценарий требует
совместной композиции с native R1: настоящий OneC-сервис, два существующих
юрлица для autoflush, настоящий native create/update и общий advisory helper.
Подменяется только внешний клиент 1С. Проверяются ожидание Ref до CP/row/DML,
commit/rollback, свежесть ссылок, dirty entry, перенос подключения, жизнь
capability и лог ошибок.

Запуск принадлежит ROOT после независимого просмотра исходников обоих
кандидатов. Общий conftest импортирует приложение и удаляет схемы раньше
защиты модуля; обычный pytest и даже collection этим документом не разрешены.
