# Исправления данных и ожиданий тестовой приёмки

Производственный код не меняется. Сохранены два исходных неуспешных прогона:
Docs7fa9:64 PASS из65; native parties1abe:166 PASS из167 на полной схеме.
Они не переименовываются в успешные результаты.

В Docs ожидание400 для неизвестного token_type_hint не совпадало с текущим
Authlib1.9.1: UnsupportedTokenTypeError наследует ForbiddenError.status_code401.
Реальный captured HTTP log подтвердил401. Обработчик API сохраняет код и
очищает JSON до одного error. Тест теперь строго проверяет401/точный JSON,
no-store и неизменность двух строк после отказа, выводит ответ при расхождении.

Это описание прежнего поведения, а не признание его соответствующим стандарту.
RFC7009§2.2 предписывает игнорировать неверный token_type_hint:
https://www.rfc-editor.org/rfc/rfc7009.html#section-2.2
Отдельная обязательная правка протокола должна изменить production, связанные
старые ожидания и OpenAPI совместно. Данное исправление её не подменяет;
17 прежних OAuth ветвей и12 canonical policies не изменены.

В тесте удаления контактного лица до вызова actual handler создавался объект
с49-символьным id для VARCHAR(40); поле code допускает100 символов. Новый id — строка
opaque: плюс32hex, всего39 символов; это по-прежнему непрозрачная строка,
не UUID. Схема, драйвер, реальные FK, handler и CASCADE assertions прежние.

Повторная совместная приёмка должна включать все65 Docs и167 native-party
случаев на одном frozen составе с полной native схемой; P1 synthetic8tables,
общий CI и рабочий пилот имеют отдельные границы. Все20+11 остаются открытыми.
