# Именованный ObjectId в каноническом OpenAPI, 30.10.2026

База кандидата: `0eb3319dffc30da8df40cdb83d0c280bb41be211`.
Ветка: `agent/api-objectid-schema-compatibility-20261030`.

По переданным координатором доказательствам новый FastAPI 0.133.0 / Starlette
1.3.1 публикует эквивалентные ограничения ObjectId непосредственно в schema
path-параметра. На FastAPI 0.115.6 / Starlette 0.41.3 там уже находится ссылка
`#/components/schemas/ObjectId`. Ограничения до правки семантически совпадали;
изменилось представление именованного типа для Swagger и генераторов SDK.
В общем прогоне нового окружения это дало единственный FAIL из 376 тестов:
`test_product_object_ids.py::test_pure_schema_distinguishes_object_identity_from_other_ids`.
Эта проверка и DTO остаются без изменений.

## Изменение

Сразу после `get_openapi` канонический издатель проверяет два известных GET:
`/objects/{objectId}` (`getObject`) и `/objects/{objectId}/monitoring`
(`getObjectMonitoring`). Для каждого нужен ровно один обязательный параметр
с `name=objectId`, `in=path`. Реестр политик описывает доступ и владельца,
но не идентичность параметра: здесь выбран явный список двух wire-маршрутов
и operationId, без поиска по префиксу и без изменений runtime-реестра.

Готовая точная ссылка сохраняется вместе с исходным объектом schema.
Inline-схема заменяется только при полном равенстве авторитетному компоненту
ObjectId; сравнение игнорирует исключительно аннотацию `title`.
Сравнивается каноническая JSON-сериализация с сохранением типов, поэтому
Python-равенство `True == 1` не может скрыть дрейф, в том числе во вложенных узлах.
В production нет второй копии ограничений ObjectId. Дополнительное неизвестное
ограничение нельзя потерять: оно должно совпасть с компонентом или публикация
завершится ValueError. Новый маршрут с path-параметром objectId, другая операция,
неверное имя/место параметра, отсутствующий компонент или маршрут также требуют
явного пересмотра. Оба узла проверяются до первой замены, поэтому отказ не
оставляет частично изменённую схему.

Публичная браузерная проекция наследует канонические ссылки существующим
deep-copy. Код runtime, ACL, идентификатор запроса, DTO, зависимости, библиотеки,
версии и параметры в других местах не меняются.

## Проверки и границы

Новый модуль содержит 13 чистых тестов: точная положительная замена, неизменность
готовой ссылки и идемпотентность, title, отрицательные варианты ограничений,
чужая ссылка и её siblings, имя/in/required и дубликаты, отсутствие компонента
или маршрута, новые пути/методы/operationId, неизменность соседних ветвей,
неизвестное общее ограничение, настоящий канонический экспорт и публичная
проекция, отказ настоящего издателя при дрейфе генератора.
Golden-ограничения, aliases, operationId и security expectations заданы в тестах
независимо от нормализатора. Отдельного запуска генератора SDK/браузера нет.
