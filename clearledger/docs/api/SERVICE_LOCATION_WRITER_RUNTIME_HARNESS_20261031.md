## Границы и негативный дизайн

Сохранён reference sendmsg policy: owned connected AF_INET/SOCK_STREAM/TCP; owned/current FD одинаковый и неотрицательный; exact peer; только buffers. В source review перечислены 16 ветвей: positive; unowned; closed; reused/detached; wrong/unconnected peer; datagram; UNIX; IPv6; RAW; other protocol; ancillary; explicit flags even zero; address; keyword flags; keyword ancillary; keyword address. ContextVar capability и exact C-call caller связывают audit event с единственным wrapper. Никаких controls сейчас не создавали и не исполняли.

FS guard покрывает open writes, rename/remove/rmdir/mkdir/utime и отклоняет link/symlink/chmod/chown/truncate вне разрешённой модели. dir_fd и неразрешённые fd mutations/dup запрещены. Low-level write/ftruncate требует capability на regular ROOT-owned single-link file, открытый этим процессом в private root, со сверкой dev/ino. Любой symlink в source/deps/private trees, ancestor или interpreter path, тип устройства/FIFO/socket в file trees, hardlink, смена inode/mode/owner, byte/file cap, чужой fd, source или input drift ведёт к отказу. Python fences относятся к reviewed frozen code; они не заявляются OS sandbox против произвольного native malicious extension. Привязка внешнего контейнера и финальные PG/PID факты остаются отдельным ROOT proof.

Обязательные будущие отрицательные проверки ROOT: неправильный/отсутствующий unique opt-in; Python flags/version/UID; изменённый self/source/fixture/original77 RECORD/module; symlink каждого корня/ancestor; stale/wrong-stage/forged lease или schema receipt; DB/roleOID mismatch; reused cwd; external DSN/HTTP/process/write/fd; missing/duplicate/extra/skipped/teardown-failed cases; source/deps drift на exception; connection cleanup timeout; resource floor/caps failure.
