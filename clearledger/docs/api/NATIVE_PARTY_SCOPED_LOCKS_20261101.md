# Native-карточки и контакты: Source-пакет

Только исходники. Новые тесты AUTHORED / NOTRUN; runtime = 0. Запуск, CI, миграция и выпуск не подтверждены. Подробные границы и исходные 20 разделов / 11 условий со статусом OPEN сохранены в соседнем JSON.

Охват: CREATE/PATCH/DELETE контрагента, CREATE/PATCH организации, CREATE/PUT/DELETE контакта в `references_router.py`. `delete_organization`, девять договорных команд R1, OneC, identity, schema и существующие тесты сохранены без изменений. Удаление организации требует отдельного решения по FK → участникам.

`native_party_locks.py` получает один полный B-план до прежнего CP-барьера, строк и первой pending-записи. Company S защищает реальные родительские компании; User S и Member S защищают native-проверку доступа. RefComposite X применяется к пяти командам карточек; S к трём командам контактов. Контакт держит CP SHARE перед своей строкой UPDATE. Именованная роль не читается прежней политикой и нового RoleKey нет.

После всех ожиданий перечитываются retained-ссылки, родительские указатели и прежние native session/visit/member/get_owned правила. Dirty/new/deleted на входе требуют отказа всего root; helper не делает flush, discard, commit или rollback. Capability относится к тому же действующему root и соединению; повторный вход и позднее расширение ключей запрещены.

Проверка дублей ИНН/КПП, verified-права, aliases, nullable-поля и manual_overrides остаются у прежних владельцев. CREATE verified проверяет права раньше дублей; PATCH проверяет дубли раньше verified. Нативные поля организации не получают новых проверок ИНН или правил очистки.

**Изменение для прямого Python caller CP DELETE:** savepoint удалён, поскольку он отравляет capability. HTTP 409 и его текст при IntegrityError сохранены; сама транзакция после FK-ошибки требует полного rollback. Продолжать или повторять команду в том же root нельзя. HTTP dependency `get_db` владеет откатом; helper транзакцию не завершает.

Тестовые определения используют реальные команды, checker и PostgreSQL sessions: обе очередности R1/OneC/контактных и User-писателей, ожидания до DML, сохранённые ссылки, pending-состояние, отмену и реальную FK-ошибку. Их guard не защищает от раннего repository conftest: перед импортом нужен отдельный состав, проверенный ROOT.

RefComposite не присоединяет автоматически импортные, location, User/Role и прочие writers. Полнота физических FK, динамические потребители и отсутствие взаимных блокировок в общей системе остаются UNKNOWN. Внешний партнёрский API этим пакетом не открывается.
