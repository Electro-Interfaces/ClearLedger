[Официальный version JSON http-ece 1.2.1](https://pypi.org/pypi/http-ece/1.2.1/json)
объявляет единственный `http_ece-1.2.1.tar.gz`, 8 830 байт, SHA-256

В этой выборке upstream wheel отсутствует. Скачанный архив соответствует JSON.

Прочитаны PKG-INFO, setup.py и setup.cfg. `pyproject.toml` отсутствует;
из AST вызова setup извлечён литеральный `install_requires=['cryptography>=2.5']`.
Динамические hooks не вызывались. Для будущего запуска предложен стандартный
legacy backend `setuptools.build_meta:__legacy__` с implicit
`setuptools>=40.8.0`, закреплённым кандидатом `80.9.0` и wheel `0.45.1`.
Это build-план, а не доказательство достаточности toolchain.

ROOT должен изготовить wheel в чистой среде без сети, вычислить его фактический
SHA-256 и сохранить отдельное свидетельство связи sdist → toolchain → wheel.
Хеш старого wheel из исторического журнала не подставлялся. Исходный манифест
подготовки остаётся неизменяемым; новый wheel и будущий lock получают отдельные
артефакты и приёмку. `--require-wheels` у проверяющего инструмента сейчас намеренно
отказывает; наличие рядом самостоятельно построенного файла не снимает блокер
автоматически.

## 5. Проверяющий инструмент и ограничения

[prepare_dependency_artifacts.py](../../server/tools/prepare_dependency_artifacts.py)
работает на Python 3.11+ и использует только stdlib. Он не импортирует приложение,
драйверы, скачанные пакеты или build backend.

- `fetch` создаёт новый приватный каталог подготовки, получает только version JSON
  с `pypi.org` и объявленные файлы с `files.pythonhosted.org`. HTTPS проверяется
  стандартным TLS context; credentials, query, fragment, нестандартный port и
  redirect на другой host отклоняются. Нет fallback hosts или правок proxy/CA.
- `verify` выполняет только чтение и не делает сетевых запросов. Он сверяет
  frozen receipt/input/baseline, уникальные pins/roles, официальное объявление
  файла, локальные размер/SHA-256, содержимое metadata и полный журнал загрузки.
- Wheel проверяется по имени/version, единственному dist-info, Name/Version,
  Requires-Python, декларациям Requires-Dist и равенству filename/WHEEL tags.
  Для sdist читаются только ограниченные metadata и AST; ничего не извлекается
  на диск и не исполняется.
- Небезопасные пути, symlinks/hardlinks к файлам набора, архивные links/special
  members, дубликаты, неверные хеши/размеры, неподдержанные markers, неизвестный
  обязательный формат и неразрешённый source fallback приводят к отказу.
- Ограниченный marker parser поддерживает известные имена PEP 508, сравнения,
  группировки, `and/or`, `in/not in`. Для runtime он проверяет синтаксис и сохраняет
  declarations; полного графа и активации всех extras не вычисляет. Для tooling
  применяется объявленная целевая среда без optional extras. Недоступные свойства
  target, необходимые для вычисления marker, не подменяются свойствами host.

Лимиты: весь сохранённый набор до 256 МиБ; один скачиваемый файл до 64 МиБ;
metadata одного архива, включая ZIP central directory и выбранные wheel headers,
до 4 МиБ; один журнал до 2 МиБ; до 10 000 members; распакованный объявленный размер
до 128 МиБ; fetch deadline до 900 с и максимум 160 запросов. Уже существующий
каталог fetch не перезаписывается, частичная неудачная загрузка и её журнал
сохраняются. Отсутствие места или превышение лимита останавливает операцию.

На момент первоначальной приёмки набор с проверочными журналами и ROOT-предложением
занимал 40 487 554 байта, менее 39 МиБ. Журнал загрузок — 36 585 байт. Реальные пути
окружения и содержимое журналов в публичный отчёт не включены.

Общий deadline — 900 с, включая 120 с резерва. Предложены до двух CPU,
1 ГиБ памяти и 256 МиБ суммарных сохраняемых артефактов. Исторический лимит
128 МиБ scratch пересмотрен ROOT до 256 МиБ tmpfs; актуальные параметры запуска
указаны в разделе 10. Лимит журнала остаётся 2 МиБ. Tooling и runtime venv
последовательно сменяют друг друга.
ROOT должен контролировать фактическое место; превышение лимита, отсутствующий
артефакт, изменение pin или ошибка compiler останавливают стадию с сохранением
журнала. Автоматические upgrades и сеть для backend/resolver/install не допускаются.

Параметры будущего compiler: `--no-config --resolver=backtracking --generate-hashes
--strip-extras --no-index --find-links` на подготовленный runtime wheelhouse,
`--constraint` на baseline и отдельный `--output-file`. Extras сохраняются
в `.in`, а зависимости extras должны попасть в полное замыкание.
Будущая установка использует `--no-cache-dir --no-index --require-hashes
--only-binary=:all:`; dependency checking остаётся включённым.

Эти команды потребуют настоящей целевой среды и выполняются следующим исполнителем
под руководством ROOT. При неизвестном marker или неподдержанном specifier следует
расширить проверяемый контракт отдельной правкой, а не игнорировать декларацию.
При отличии графа от 59 наблюдавшихся пакетов нужен разбор причины без молчаливой
подмены baseline. При несовместимости pip-tools/pip новая пара версий выбирается
явным изменением и получает новую проверку.

Отдельно остаются base/APT snapshot, повторная независимая сборка и сравнение
результатов, функциональная совместимость и выпуск. Текущая подготовка не меняет
Dockerfile, runtime requirements, test requirements, Compose или CI.

## 9. Исправление числового сравнения после независимой проверки ROOT

ROOT обнаружил дефект инструмента: исходный вызов
`satisfies('1.0.0.0.0.0', '==1.0')` возвращал `False`. Это исторический дефект
сравнения в исходнике, а не отказ выбранного артефакта. Дополнение release только
до пяти компонентов не соответствовало правилу сравнения PEP 440: более короткий
release дополняется нулями до длины второго операнда.
[PyPA: final releases](https://packaging.python.org/en/latest/specifications/version-specifiers/#final-releases)

Теперь общая функция сравнения дополняет до фактической длины операндов. Она
используется всеми числовыми операторами и numeric markers. Для wildcard-prefix
нулевое дополнение применяется к сравниваемому префиксу; для `~=` сохраняется
исходное число компонентов границы при вычислении верхнего предела. Например,
точность `~=1.0` и `~=1.0.0.0.0.0` намеренно различается.
[PyPA: compatible release](https://packaging.python.org/en/latest/specifications/version-specifiers/#compatible-release)

Поддержанный subset явно ограничен: до 128 компонентов release, до 32 ASCII-цифр
в компоненте и до 4096 символов. Epoch, pre/dev/post/local версии и значения вне
границ не получают приближённый boolean: они отклоняются. Проверяются все clauses,
поэтому ранний `False` не скрывает неподдержанную последующую границу.

Добавлены шесть новых тестовых методов: исходный reproducer, обе длины операндов,
длинные нулевые хвосты, ненулевой хвост и порядок после пятого компонента,
wildcard precision, compatible upper bound, обратные numeric markers и явные
отказы за границами subset. Прежние 19 проверок сохранены.

| Финальная проверка исправленного исходника | Результат | SHA-256 нового журнала |

## 10. Конкретный приватный драйвер следующих стадий ROOT

Подготовлен `target-stage.py`, 34 968 байт. Его исходник просмотрен, разобран AST
и скомпилирован встроенным `compile`; **драйвер не импортировался и не запускался**.
Ни один его subprocess, venv, installer, compiler или backend здесь не выполнялся.
Драйвер и новое предложение находятся в приватной области; в Git опубликованы
только эти контрольные суммы:

| Артефакт | SHA-256 |
|---|---|
| Драйвер ROOT | `a98940f0624f48305331dc0da97c96ab4f682756e6f3c49d682e3f0c51e2a5f7` |
| Новое предложение ROOT с layout, argv и контрактом | `3165e3a06e2143bb1ccace99f165c854c2f7084f07a98d9a6cafcbac59548edb` |

Предыдущий файл предложения с SHA-256 `3d38bbd9…` не перезаписан. Новое предложение
предназначено для исполнения после проверки ROOT; исходный манифест подготовки
остаётся историческим входом с source-only блокером.

ROOT самостоятельно выполняет preflight точного ранее проверенного образа
`sha256:812e423c722ae3cbac7780e4d8bd1ac54387b27c013c33f89c9c1fdefb7cae51`
и его неизменяемого архива. Драйвер не запускает Docker, не пересобирает образ
приложения и не меняет runtime. Запуск предусмотрен с `-I -S -B` под nonroot,
с выключенной сетью, read-only root, двумя CPU, памятью 1 ГиБ, pids 128,
отдельным tmpfs 256 МиБ, только безопасными read-only inputs и свежим writable output.

В новом контракте scratch — **256 МиБ**. ROOT сообщил измеренный суммарный
распакованный размер 58 runtime wheels: 112 348 570 байт; вместе с pip/venv
исторический лимит 128 МиБ недостаточен. Драйвер читает реальные target-факты:
Python patch, ordinary `cp313`/SOABI, GIL, Linux/x86_64 и glibc. Он проверяет mounts,
отсутствие сетевого интерфейса кроме loopback и cgroup v2 limits. Значения glibc
с машины подготовки не используются вместо фактов целевого контейнера.

Подготовленные стадии драйвера:

1. Проверить frozen input hashes, все 65 JSON/артефактов, отдельный finder ровно
   из 58 исходных runtime wheels, 22 direct и три extras. Дополнительно проверить,
   что runtime wheels не добавляют `.pth` или sitecustomize/usercustomize hooks.
2. Создать свежий tooling venv без system site packages. Установить ровно восемь
   hashed pins offline, сверить полный состав через stdlib metadata и pip check.
3. Перепроверить конкретный просмотренный setup.py по SHA-256 и безопасно извлечь
   regular files/directories sdist. Изготовить wheel без isolation и без сети;
   перед compiler проверить его identity, metadata, tags и фактический SHA-256.
4. Дать compiler только read-only finder с 58 wheels и output с одним новым wheel.
   Получить отдельный provisional lock, требовать точное замыкание из 59 pins и
   единственный утверждённый wheel hash каждого пакета. Drift или несовместимость
   pip-tools/pip останавливают работу с сохранением защищённого журнала.
5. Сохранить свидетельства и удалить только собственный tooling/source scratch.
   Создать новый runtime venv, отдельно закрепить pip `26.2.2`, выполнить offline
   установку с hashes/only-binary и dependency checking. Проверить полный состав
   59+pip через metadata без импорта пакетов, затем pip check.
6. Удалить только принадлежащий драйверу scratch. Сохранить новый wheel, provisional
   lock, журналы и receipts; результат не объявлять выпуском или exact rebuild.

Для процессов предусмотрены ограниченный capture, отдельная process group,
остановка группы и обязательный wait/reap. Таймауты фаз — 60/180/120/180/180/60 с;
общий deadline 900 с, 60 с зарезервированы для очистки. ROOT также обеспечивает
жёсткий срок жизни контейнера. Журнал ограничен 2 МиБ на файл и фазу, retained
output — 256 МиБ, scratch — 256 МиБ. Временные outputs backend и compiler
остаются в собственном tmpfs scratch;
в retained output переносятся проверенный wheel и provisional lock. Output
допускает только ожидаемые файлы; нет сетевого fallback, повторных попыток
обновления или автоматической смены pins.

Эти свойства проверены чтением исходника и AST/compile, **не целевым запуском**.
Все настоящие target phases, installation, compiler, backend, wheel build,
offline install и pip check остаются `NOT RUN`. Приложение/драйверы БД, SQL,
CI, среды и выпуск не затрагивались.
