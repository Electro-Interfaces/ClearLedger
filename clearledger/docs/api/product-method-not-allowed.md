# Ответ 405 и заголовок Allow в product OpenAPI

Все 17 существующих операций (16 GET и POST `/contracts`) формально описывают
ответ `405` через готовые компоненты `ProductMethodNotAllowed` и
`ProductContractsMethodNotAllowed`. Описания используют `application/problem+json`,
схему `Problem`, код `method_not_allowed` и обязательные заголовки
`Allow`, `Cache-Control: no-store`, `X-Request-Id`.

| Путь | Значение Allow при неподдерживаемом методе |
| --- | --- |
| `/contracts`, обе операции GET и POST | `GET, POST` |
| Остальные 15 путей, включая `/contracts/create-options` | `GET` |

Публичная браузерная проекция сохраняет те же ссылки ответов и компонентов.
Для известного пути неподдерживаемый метод получает 405; неизвестный путь
получает 404 с кодом `not_found` без заголовка `Allow`.

Привязка добавлена только в метаданные схемы. Состав операций, обработчики,
проверки доступа и маршрутизация сохранены. Ошибки прокси и ошибки после начала
потокового ответа остаются за пределами этого контракта приложения.

В существующий модуль `test_product_openapi_http_contract.py` добавлены пять
определений: все 17 operation contracts и браузерная проекция; отрицательные
проверки отсутствующего/неизвестного ответа и неверного/необязательного Allow;
ASGI 405 по известным путям и ASGI 404 по неизвестному пути. Доступ к сессии
и verifier в новых сценариях закрыт падающими guards без положительных identities.
Определения не запускались (NOTRUN); статический разбор и компиляция исходного
текста не подтверждают runtime-приёмку. Генерация SDK выполняется отдельно.
