## Фактическая граница CP-01

`CORE_PROTOCOL_CURRENT_20261031` указывает handshake-only lifetime gap, независимо от исправленного query logging. В текущем `chat_ws` JWT/User/session_valid проверяются до accept; manager сохраняет user/company IDs, но не exp/tv/at/scope. Сокет может ждать receive, отвечать pong и получать обычные push events без повторной проверки signed session lifetime. Подписка/typing вызывают DB ACL, но передают сохранённый User. HTTP refresh не заменяет authority уже принятого сокета.

Рекомендуется один native WS session owner: validated immutable signed-claims descriptor, локальная проверка deadline на каждом send/operation, coalesced current-user/session checks короткими DB sessions, existing room ACL owner и generation-guarded frontend reconnect с **предварительным** refresh. Это конкретный proposed package для последующего ROOT implementation GO, не разрешение писать код сейчас. Значения sampling/check budgets ROOT замораживает после измерений; source presence20s предлагается лишь как начальный measured target, не новая business TTL.

## Рекомендуемый lifetime owner и cadence

Proposed immutable NativeWsSession: actual user UUID, validated native tv/optional at, finite exp, visit cid/pvs если есть, verified tenant selection, connection epoch. Не содержит fake User/service principal/raw bearer/email/name в persistent channel metadata. User ORM загружается свежим внутри каждого required authority check и не хранится как lifetime permission; name для typing берётся из текущей проверки/ограниченного metadata snapshot, не authority.

Handshake и subscribe/typing — fresh current session+channel admission перед действием; объединять auth и ACL в одной короткой session, не вызывать HTTP get_current_user и его presence commit на каждый кадр. Ping/unsubscribe/unknown frames используют local deadline/closed guard; полный auth SQL не выполняется на каждый byte/pong/notification. Idle watchdog/coalesced due gate проверяет current User/tv/visit/member; ordinary room eligibility проверяется coalesced по `(session epoch,channel)` при due delivery/scan. Existing payload-specific task/ticket/history checks остаются на каждом прежнем send, с их прежней ценой; обещания «вообще нет SQL на notification» нет.

**Cadence C — sampling window, не business session TTL.** Source already has20s worker presence heartbeat;20s — лишь начальный performance/security measured target для проверки, не утверждённая новая настройка/лимит. C/check-budget/concurrency/drain freeze задаёт ROOT до реализации/actual; без его выбора нельзя объявить revoke мгновенным. Worst-case authorization observation — C + measured scheduling/check latency; когда proof due/unknown или check failed, новые protected sends fail closed/ждут ограниченный check, не обслуживаются stale proof бесконечно. Room revocation не создаёт данные при отсутствии events; перед следующим due delivery нужен current probe. New subscribe/typing обязаны fresh admission, не используют старый cached allow.

Single-flight на validation identity/connection epoch, не один глобальный lock всех sockets. Два known consumers в одной вкладке не должны удваивать expensive refresh/check без необходимости; cache результата не переживает epoch/tenant/claims change и не становится global session authority. CPU/SQL/role probes на N rooms и two-socket fixture измерить; нет предложенного lifetime room/connection cap, новых глобальных auth flags или schema table.

Контекст checks изолирован: pure shared native helper не пишет request-global claims, periodic room probe не вызывает audit/notify. `_check_visit` обязательно reused с fresh DB; tenant callback в shared chat ACL возвращает только уже проверенный connection tenant. Для callbacks, вызывающих auth helpers с ContextVar side effects, выполнить check в одном tracked child task с изолированным context и закрыть session до возврата либо scoped owner reset tokens; **выбор одного seam ROOT замораживает**. Нельзя переносить stale visit/object/company ContextVars от получателяA кB в одном manager loop. Background check не импортирует routers и не создаёт словарь generic callbacks. Публичный `assert_participant` остаётся wrapper с late-bound hooks и прежними SQL/denial/audit traces; pure eligibility extraction нужна для periodic probe без почтовых уведомлений каждые C.

## Expiry, clocks, revoke и safe close

Source exp — signed NumericDate; primary check wall UTC по тем же semantics, что native decode. Локальный send gate проверяет expiry **после** каждого await и прямо перед send. Watchdog просыпается по ближайшему exp/session horizon/check_due, не ждёт client ping. Не продлевать connection lease при каждом кадре/presence. Проверка at ceiling повторяет actual session_valid (`>`/optional at), не выдумывает новый7-day countdown.

Monotonic нужен для bounded waits/cadence и измерения elapsed; wall clock — для signed exp/session_valid. Source не доказывает NTP behavior. При forward clock jump send gate должен закрыть при следующей операции независимо от старого wakeup; idle detection дополнительно ограничена C. Backward jump не должен бесконечно продлять уже наблюдённый deadline/cache: conservative monotonic deadline из проверенного remaining exp и terminal closed state может закрыть раньше, но не позже наблюдённого срока; это proposed clock semantics, требует literal boundary/jump tests ROOT, не live clock adjustment. После закрытия clock rollback не возрождает socket.

## Cancellation, rollback, process drain и ограничения

Read-only authority/check sessions завершаются и connection released **до** ожидания client receive/send; на error/cancel rollback/close, CancelledError не глотать как success. Никакая ORM session/transaction/row lock не живёт столько, сколько socket. Existing presence and last_seen writes допустимы только в прежних коротких transactions, не в периодическом native verifier. No SMTP/COM/jobs/delivery side effects от periodic eligibility; explicit subscribe/typing retains old late-bound audit/notification hook semantics, source сейчас может запланировать dispatch даже без durable audit commit. Это отдельный existing audit durability unknown, не поручение исправить его здесь.

Shutdown: stop new delivery admission→invalidate/close session epochs→cancel & await check/watchdog/receive-owned child tasks→close/drain sockets with known safe reason→cancel listener/presence→remove/listener.close→await/reap tracked delivery tasks→presence cleanup. Точный порядок совмещается с existing manager.start/stop ownership; не ждать gather бесконечно и не запускать новый background retry после terminal stop. Measured drain/check/send budgets ROOT freezes, не worker-installed timers/новый service. Per-socket cleanup exactly once, repeated disconnect no duplicate offline/last_seen; never await external Support/SQL while global map lock held.
