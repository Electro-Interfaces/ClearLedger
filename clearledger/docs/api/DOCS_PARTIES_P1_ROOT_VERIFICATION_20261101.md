# API: портал документации, контрагенты и юрлицо участника

ROOT завершил два отдельных тестовых профиля; независимая SOURCE+RAW приёмка
обоих принята без открытых findings. Результат не является общим CI или
готовностью всего API к выпуску.

**232 PASS на одном составе ca672dd7:**65 сценариев выхода из портала
документации и167 сценариев контрагентов, организаций и контактных лиц.
199 PG и33 source/unit случая,59 определений,696 успешных фаз,312.44с. Реальная native схема:341 модель,
347 таблиц после revision4,803 проверенных FK и3212 включённых RI triggers.

Портал проверяется через реальный ASGI HTTP, OAuth authorize/consent/token,
JWT и cookie/Origin/CSRF. Проверены повторный выход, отзыв/истечение, изменённые
связи, ожидания блокировок, откат после flush, отмена, CASCADE и изоляция сессий.
Это проверка logout, а не браузерная приёмка всего Swagger Authorize/Try it out.

Восемь native операций: создание/изменение/удаление контрагента, создание
и изменение организации, создание/изменение/удаление контакта. Выполняются
настоящие обработчики и SQL с наблюдаемыми ожиданиями, свежей проверкой прав,
foreign-company и FK/CASCADE проверками. Claims здесь программные: HTTP/JWT
транспорт native CRUD этим набором отдельно не проверялся. Org DELETE в эти
восемь операций не входит; его полная цепочка владельцев остаётся открытой.

**96 PASS в отдельном профиле P1:**31 unit и65 PG случаев назначения юрлица
участнику,28 определений/288 фаз,26.28с. Независимое SOURCE+RAW ревью принято.
Проверены оба порядка actual legacy Org DELETE и actual Source8 Org UPDATE,
self actor, commit/rollback, дрейф после ожиданий и отсутствие DML до отказа.
Исходная fixture содержит8 таблиц с ослабленной nullable и выбранными8 FK;
она не является полной native схемой и не доказывает закрытие всех22 FK Org.

Для компании контакта добавлена одна каноническая UUID-колонка на границе
результата ORM. Ядро ключей, драйвер и bind/literal обработчики сохранены.
Два тестовых дефекта исправлены без изменения production: ожидание текущего
Authlib401 вместо400 и длина opaque ID39 вместо49 для поля VARCHAR40.
Стабильный AST guard сохраняет29 исходных policy fingerprints;8 source
проверок отдельно прошли на Python3.11 и3.13.

## Соответствие протоколу

Фактический ответ на неизвестный token_type_hint записан отдельно:
401/{error:unsupported_token_type}, cache-control:no-store. Это подтверждённая
совместимость текущей библиотеки, не соответствие RFC7009. В §2.2 требуется
игнорировать неверный hint. Отдельная production/тесты/OpenAPI правка передана
в работу; текущая приёмка logout её не подменяет.

Источник: [RFC7009, §2.2](https://www.rfc-editor.org/rfc/rfc7009.html#section-2.2).

## Границы и следующий шаг

В каждом принятом профиле удалены два собственных тестовых контейнера,
соединений/блокировок PG0/0, пул закрыт на живом цикле событий без ERROR.
Совпали41 ограниченная безопасная проекция других контейнеров; полного
аттестования окружения это не даёт. Все ранние неуспешные результаты сохранены.

Следующие пакеты: управление CREATE-профилем партнёрского приложения
(source59757724, draft111) и native создание документа (source36715b3c).
Для них переданы результаты проверки исходников, runtime/интеграция ROOT впереди.
Открыты SQL-issued generation/receipt/options/partner POST, исторические
миграции, общий CI/SDK и рабочие пилоты. Все20 исходных разделов и11 требований
сохранены; общий процент и релизный GO не объявляются. Merge/выкатки/активации нет.

Парный JSON содержит точные Source и hashes результатов/очистки/независимой приёмки.
