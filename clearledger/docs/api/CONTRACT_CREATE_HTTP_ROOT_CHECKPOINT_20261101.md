# Внешнее создание договоров: состояние проверки

В ветку интеграции включён POST /api/v1/contracts с правом contracts:create. Пользовательский и конфиденциальный машинный клиент проходят исходную авторизацию. Новый договор возвращает 201, повтор с тем же ключом создания — 200. Договор, его объекты, запись идемпотентности, её объекты и аудит сохраняются одной транзакцией. Доступ на создание не выдаёт доступ на чтение. Рабочие флаги остаются выключенными.

Это промежуточный результат. На исходниках 8cda12d9 первый прогон завершился с **16 диагностическими успехами и одной ошибкой из 17**, поэтому весь состав не принят. Реальные HTTP-запросы обоих клиентов успешно создали договор и выполнили повтор. Ошибка обнаружена в Swagger: из встроенного описания необязательного comment исчезало default: null. Подготовлена ссылка на канонический компонент модели; исправление пока проходит независимое ревью.

Отдельный прогон шести сценариев ошибок завершился с **одним диагностическим успехом и пятью ошибками**. Три сценария подтвердили отсутствие бизнес-изменений и активной транзакции, затем остановились на неверной отметке закрытия сессии в тесте. Внутренняя отмена запроса преобразовывалась middleware в HTTP-ошибку. Проверка внешней отмены не достигла нужной точки: ожидание в тесте было пять секунд при фактических 5,9–6,3. Подготовлены точечная замена middleware, наблюдение настоящего закрытия и ограничение ожидания 30 секунд только в тесте. Ошибочные прогоны сохранены; исправленные сценарии ещё не приняты. Повтор после потери подтверждения commit прошёл в диагностическом составе.

Независимо принята **регрессия профилей доступа: 95 PASS / 26 функций / 285 фаз** на cdb65361. Проверены реальные ASGI HTTP, native JWT, административные права, CAS поколения, отзыв и откат после изменения общих блокировок. Время всей проверки с подготовкой — 58,592 секунды; это не время одних тестовых вызовов. Манифест исходников восстановлен после исполнения и явно обозначен таким; проверки контроллера до и после запуска сохранены. Проверяющий подтвердил 559 исходников и результаты. Его ограничения по независимой аттестации OID/host-сессии и узкому typed-drift oracle сохранены. Результат не переносится на состав с новым POST.

Полная SQL-матрица из 122 сценариев повторяется на 8cda12d9 семью отдельными сериями. Предыдущий состав остановился на неверной тестовой конструкции: два настроенных bind фактически использовали одно соединение. Исправлен только тест; настоящий отрицательный случай отдельно подтверждает два соединения, две транзакции и два PostgreSQL PID. Прежние 60 успешных случаев и непрошедшая серия остаются историческими результатами.

Все завершённые здесь среды используют полную native структуру 341 модели / 347 таблиц. Соединения и блокировки освобождены, временные контейнеры удалены штатно. Отчёт независимого ревью различает 803 физических FK и 802 нормализованные связи: у одной связи два существующих ограничения. Изменения схемы ради этой разницы не выполнялись.

Код полной защиты регистрации документов зафиксирован отдельно: 11 файлов, 33 новых определения и 89 статических вариантов. Он проходит независимое ревью; тесты ещё не запускались, прежние 84 PASS на него не переносятся.

Исходные M00–M19 и 11 сквозных требований сохранены. Открыты полная SQL/HTTP-приёмка, регистрация документов, options, активация, обновление SDK, права получателей уведомлений, остальные разделы API и пилот. Общий процент, общий CI и готовность к выпуску не заявлены. Merge и выкатка не выполнялись.

Точные исходники, квитанции, SHA-256 и состав завершённых SQL-серий приведены в парном JSON. Отчёт фиксирует момент проверки; последующие серии его не меняют автоматически.
