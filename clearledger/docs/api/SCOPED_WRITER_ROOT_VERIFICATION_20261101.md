Независимое Source+RAW review не нашло оснований отвергать этот ограниченный
результат. Это не проверка остальных операций или всех вариантов подключения.

Во втором прогоне16 случаев упали до захвата плана: SQLAlchemy2.0.36 не принимает
регистрацию Connection commit listener при вложенном dispatch от OptionEngine
с schema_translate_map. Минимальный первый состав такой вариант не покрывал.
Причина локализована по исходникам SQLAlchemy; исправление helper поручено его
владельцу с сохранением lifetime/poison и новыми PG regression cases.
Остальные2 падения вызваны AST oracle: обход всей AsyncFunctionDef включает
HTTP decorator router.delete и ошибочно считает его DB mutation до entrance.
Эти проверки также возвращены владельцу для исправления без удаления случаев.
Исходные FAIL сохранены, повтор ещё не выполнен.

Все временные контейнеры завершены и удалены обычным удалением; безопасные
проекции чужих контейнеров совпали до/после. У принятого PG-прогона остаточных
клиентов и блокировок0/0. Unit «Магазина» выполнялся без сети и PostgreSQL.

нулевой счётчик не используется как доказательство отсутствия SQL.
