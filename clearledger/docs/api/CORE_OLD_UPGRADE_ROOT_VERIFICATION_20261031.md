# Core: обновление прежних схем и сохранение данных

ROOT принял 8 из 8 сценариев OLDUP в отдельных прогонах. Общий компонентный итог: 55 различных ID из 57 в 50 сериях; осталось 2. Это не один общий зелёный прогон и не завершение всей программы API.

## Изменение кода

Явный bootstrap проверяет исходный профиль схемы, создаёт согласованные предпосылки и передаёт управление versioned runner. Обновление прежней партнёрской схемы до ревизии 0003 выполняется под единым владельцем соединения и блокировки. Неизвестная, повреждённая или частично занятая схема получает определённый отказ до миграционных записей.

Исходный коммит PR93 `4224ab4a9ab724f57f784260705ee5c32b2cddb6` перенесён в ROOT PR78 как `19acce541ed213f78af087c03a19ad84bc16867d`. Все 14 файлов побайтно совпали; семь Python-файлов прошли разбор и компиляцию в памяти. Исторический отчёт FactsOnly7 внутри этих 14 файлов сохраняет прежний срез 45/57. Текущий результат приведён здесь. Общий runtime интеграционного ROOT HEAD ещё не проверен.

## Проверка оснастки

Независимый SOURCE-review обнаружил пробел в положительном acceptor V1: отсутствие detail могло пропустить проверку дочерних квитанций. До native-прогонов применён V2: обязательные словари/ключи, точный integer exit0, reaped=true и равенство parent/raw. Prepare/run/read побайтно сохранены. В первом ce94 использована только подготовительная metadata V1; исполнение, capture и приёмка уже V2. Повторного native-прогона ради исправления acceptor не было.

Отрицательные записи могут не сериализовать дочерние detail: их настоящие raw-квитанции и завершение проверены отдельно вместе с frozen parent wait/reap и внешними переписями. Отсутствующие поля не объявляются наблюдёнными значениями.
