# Общая идентичность контрагентов в импорте платежей

Импорт больше не удаляет правовую форму и не выбирает последнюю карточку из
словаря одинаковых имён. Он использует существующий `CounterpartyIndex` из
`reference_identity`: правовая форма сохраняется, известные source/manual
aliases учитываются, несколько кандидатов дают явную неоднозначность.
В индекс входят только настоящие контрагенты выбранной компании, без групп.
Карточки и договоры этот путь не создаёт.

Повтор загрузки сохраняет действующую связь с настоящим контрагентом той же
компании. Новый кандидат не заменяет её автоматически; результат сообщает
`existing_link_retained`. Чужая/group ссылка не сохраняется как разрешение.
Ключи источника, суммы, периоды и агрегация строк остаются прежними;
состояние закрытия месяца не меняется. Commit по-прежнему у вызывающего use case.

В ответ добавлены `counterparties_ambiguous`, `counterparties_unmatched`,
`counterparties_retained`, `identity_issues`, `identity_issues_truncated`.
Первые два счётчика описывают результат текущего сопоставления, retained
может пересекаться с ними. Issues ограничены 100 строками с явным truncated;
это результат импорта, не новый сохранённый статус карточки.
`counterparties_matched` считает однозначные совпадения с итоговой связью.

Проверено на PostgreSQL с синтетическими данными: правовые формы, дубли,
группы/чужая компания, manual/source alias, сохранение связи при replay,
отказ сохранять чужую ссылку, конкурентные повторы и закрытый период.
17 payment/shared-identity тестов PASS, дополнительная проверка ограничения
issues PASS. Обновление типов и пояснений интерфейса следует после интеграции
текущего владельца `opsService.ts`.

Это часть M06: остальные import/CRUD paths и scope/contract команды требуют
отдельной приёмки. Рабочие платежи не загружались и не перепривязывались.
