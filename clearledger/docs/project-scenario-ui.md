# Настройки сценариев проектов

Поверхность работает в режиме **Operate** внутри существующего рабочего места
проектов. Визуальный канон — [DESIGN.md](../DESIGN.md), продуктовый контекст —
[PRODUCT.md](../PRODUCT.md). Используются общие кнопки и поля, текущие токены обеих
тем, текстовые статусы, списки с разделителями и раскрываемые подробности этапов.
Отдельной визуальной системы у сценариев нет. Подключённое приложение открывает
свои разделы по маршруту «Проекты» у любого профиля компании.

Реализация: [ProjectScenarioSettings.tsx](../src/components/sites/ProjectScenarioSettings.tsx)
и [ProjectOverviewTab.tsx](../src/components/sites/ProjectOverviewTab.tsx).

## Черновик, готовность и публикация

Редактор открывает сохранённый черновик, если он есть; иначе — опубликованный
сценарий. Название вида работ берётся из опубликованной версии. Рядом видны номер
версии для новых проектов и наличие сохранённого черновика.

| Состояние | Поведение интерфейса |
|---|---|
| Загрузка | Текст «Загрузка сценариев…» со статусом загрузки. |
| Ошибка загрузки | Сообщение ошибки, «Повторить» и «К проектам». |
| Сценариев нет | Текст «Сценарии ещё не настроены». |
| Только просмотр | Настройки видны, поля отключены; кнопок сохранения и публикации нет. Причина объяснена рядом с формой. |
| Есть несохранённые правки | Основное действие — «Сохранить черновик». Публикация, выбор вида работ, «К проектам» и открытие учебной закупки отключены. «Отменить правки» возвращает исходное содержимое редактора. |
| Черновик сохранён | Повторное сохранение без правок отключено. Готовность относится к сохранённому состоянию. |
| Черновика нет | Его можно создать сохранением текущего сценария без дополнительных правок. |
| Готов к публикации | «Опубликовать для новых проектов» доступно при наличии черновика, положительной готовности и отсутствии несохранённых правок. |
| Сохранение или публикация | Поля, сохранение, публикация, выбор вида работ и возврат к проектам временно отключены. |
| Ошибка записи | Показаны сообщение и «Отменить правки и обновить»: действие отбрасывает локальные изменения и запрашивает актуальные настройки. |

Готовность показана отдельным списком: у каждой проверки есть текст и значок
результата. Проверяются подключения приложений, выбранные сотрудники и шаблоны.
Несохранённые изменения требуют сохранения для повторной проверки. Готовность не
подтверждает работу внешних поставщиков и учётных систем: это проверяется при
выполнении работы.

Публикация применяется к новым проектам; действующие сохраняют свою версию.
Предыдущие версии доступны в раскрываемом списке с названием и последовательностью
этапов. В обзоре проекта видны его версия, текущий этап и ссылка «Настройки для
новых проектов».

## Состав сценария

Настраиваются название, подписи полей, последовательность этапов и действия
приложения в Чате. Для этапа задаются ожидаемый результат, способ подтверждения,
исполнитель по умолчанию, срок новой работы в календарных днях, шаблон Трека и
обязательные сведения. Этапы перемещаются кнопками «Выше» и «Ниже»; в сценарии
остаётся хотя бы один этап. Полей и этапов может быть не больше тридцати каждого вида.

Для согласования и подписания список шаблонов ограничен документами. Недоступные
сохранённые сотрудники и шаблоны остаются видимыми с объясняющей подписью. Ошибка
загрузки справочников не очищает настройки; доступен повторный запрос.

В обзоре проекта заполнение полей и выбор шаблона отделены от принятия результата.
Для принятия требуется выбрать подтверждающую работу. Текущий этап выделен текстом
и цветом, принятые результаты подписаны «принято».

## Учебная закупка

Учебный пример открывается отдельным действием, когда сервер сообщает о его
доступности. Перед запуском указано, что будут подготовлены проект, три вымышленных
сотрудника, обсуждение и пять работ с документами. Во время подготовки кнопка
отключена; ошибка отображается рядом. Повторное открытие возвращает тот же пример
с сохранённым результатом.

В обзоре учебного проекта раскрывается инструкция с ролью руководителя, ссылками
на работы и способом подтверждения каждого этапа. Участники и документы названы
вымышленными. Инструкция предлагает пройти работу, вернуться в проект и принять
результат; отдельно описано внешнее ожидание на этапе поставки. Пример не создаёт
факт оплаты и складские остатки.
