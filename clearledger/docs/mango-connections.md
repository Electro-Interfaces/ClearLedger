# Mango в общем приложении «Подключения»

Администратор организации открывает «Подключения → Состояние → Добавить подключение
→ MANGO OFFICE ВАТС». Название, ключ API, ключ подписи, линии, включение, адрес
событий, проверка связи и загрузка истории за сутки доступны в одном редакторе.

Дополнение: «Обновить справочники Mango» загружает сотрудников, группы и линии.
Сотрудник сопоставляется с существующим пользователем Поддержки; разрешение
исходящего звонка задаётся отдельно. Здесь же выбираются расширенная статистика,
исходящая линия и распределение входящих на ответственного/дежурную группу.
Команды звонков и распределение изначально выключены. Для дополнения требуется
миграция Поддержки `170_mango_operations.sql`; инструкция — `TSupport/docs/mango-api-expansion.md`.

## Владение и права

Настройки и зашифрованные ключи хранятся в Поддержке. Ядро не создаёт вторую запись
коннектора и не сохраняет секреты. Каталог полей приходит от владельца; для Mango
он задан в `TSupport/shared/connector-catalog.json` и используется обеими формами.

Каждый запрос проверяет членство и права администратора организации. Компания
сопоставляется с Поддержкой через `AppCompanyLink`; служебный RS256-токен содержит
`svc=connections`, идентификатор компании владельца в `cid` и автора в `actor`.
Токен проекции не даёт права менять настройки. Публичный ответ содержит только
признаки наличия ключей. В аудите Поддержки остаются автор и имена изменённых полей.

## Поведение редактора

- Новое подключение выключено. После сохранения ключей можно проверить доступ
  к статистике; включение требует оба ключа. Проверка не импортирует звонки.
- Пустое поле сохраняет прежний ключ, отдельная кнопка отмечает его удаление.
  Поля ключей очищаются после подтверждённого сохранения, при ошибке ввод остаётся.
- Повтор создания после потерянного ответа использует тот же UUID без дубликата.
- При каждом открытии редактор ждёт свежие настройки с сервера. Смена организации
  закрывает его без автосохранения. Проверка и загрузка требуют сохранённых настроек.
- Адрес событий копируется после сохранения; при отказе буфера обмена есть
  инструкция для ручного копирования. История загружается по ID выбранного коннектора.
- Если владелец недоступен, не обновлён или не связан с организацией, каталог
  показывает причину. Провайдеры без управления по API открывают прежнюю форму владельца.

  RS256, прав, карты компаний, маршрутов и совместимости служебных токенов.

- Браузер: 1440 px/светлая и 390 px/тёмная тема; создание, потерянный ответ и повтор,
  редактирование/удаление ключей, проверка, включение, история, копирование и его отказ,
  свежие значения после повторного открытия, смена организации, ограничение участника.
  Ошибок страницы нет; завершающая проверка интерфейса пройдена.
- `npm run typecheck` и адресный ESLint проходят в текущем рабочем Ledger с этой
  правкой. В чистой базе `fuel-edition`, от которой отделена ветка, есть прежние ошибки

  дерева. Эти файлы не включены в коммит Mango. Сборка и типы Поддержки проходят.

## Поставка

Нужно обновить сервер и фронтенд Ядра вместе с образом Поддержки, содержащим `shared/`.
Миграций Ядра нет; для телефонии Поддержки нужны `136_call_recording_id.sql` и
`168_mango_api.sql`. При поставке отдельно проверить состав исходников Ledger:
зелёная проверка рабочего дерева не означает готовности всех соседних изменений.
Настройка SSO и карта компаний должны работать до создания подключения.

Выкачка в пространство, активация услуги Mango и живой звонок в этот проход не
выполнялись. Требуются целевая организация, активный API-коннектор и его ключи.
Полная инструкция, вебхуки и ограничения: `TSupport/docs/mango-connect.md`.
