# Проверка целостности складского учёта оборудования

Раздел учитывает физические экземпляры оборудования и количественную номенклатуру.
Поставки, документы движения и документы ЗИП используют общий порядок дат и закрытый
период. Будущий обмен с бухгалтерией не заменяет эти проверки.

## Сохранение оснований

- При смене поставщика повторно проверяется итоговая пара «контрагент — договор».
- После приёмки реквизиты накладной сохраняются неизменными. Примечание можно
  дополнить, в том числе после закрытия связанного договора.
- Проверка повтора накладной работает при создании и изменении номера, даты
  или поставщика. Это прикладная проверка, не новый уникальный индекс PostgreSQL.
- Номер и дата первичного документа выводятся в печатных формах оборудования и ЗИП.

## Количество, стоимость и история

- Количество экземпляров целое. Количественная номенклатура допускает до трёх
  знаков после запятой. Цена конечная и неотрицательная.
- Номенклатура с учётом по экземплярам не проводится документом количественного ЗИП.
- Поступление из поставки соблюдает порядок дат движений тех же позиций склада.
  Проверка выполняется после блокировки остатков.
- Отмена оборудования учитывает последующие движения поставок, даже когда у них
  нет `document_id` документа движения.
- Отмена ЗИП требует сначала отменить последующие движения затронутой позиции
  и склада. Иначе старую стоимость можно вычесть из остатка, уже оценённого по
  другой средней цене, и получить расхождение суммы с журналом.
- Приёмка единицы без серийного номера сохраняет введённый инвентарный номер.

## Регрессия

Из `clearledger/server` на отдельной PostgreSQL:

```bash
TEST_DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@127.0.0.1:PORT/equipment_test \
python -m pytest tests/test_equipment_integrity.py tests/test_ezs_accounting.py \
  tests/test_equipment_docs.py tests/test_equipment_reports.py \
  tests/test_spare_docs.py tests/test_info_seed_equipment.py -q
```

`tests/conftest.py` пересоздаёт тестовые схемы; рабочая база для этой команды
не подходит. Набор проверяет настоящий PostgreSQL и HTTP приложения: складской
жизненный цикл, атомарность отказа группового документа, связь с компанией,
закрытый период, отмену и валидацию первичных реквизитов.

Отдельная браузерная приёмка должна пройти поступление, перемещение, сохранение
после обновления, отмену, дробный ЗИП, печать и выгрузку всего отбора на desktop
и mobile. Наличие в карточке полей 1С не подтверждает действующий обмен с 1С.
