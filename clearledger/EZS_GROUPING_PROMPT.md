| Слой | Файл |

| Эндпоинты | `D:\Users\magsp\ELSYPLUS\Ledger\app\clearledger\server\app\routers\analytics_router.py` (`/charge-sessions/grouped`, `/grouped/detail`, `/group-catalog`) |

| Клиент API | `D:\Users\magsp\ELSYPLUS\Ledger\app\clearledger\src\services\analyticsService.ts` |

Реализовано 15 разрезов (`GROUPS` в `charge_grouping.py`), сгруппированных
по семействам: **сеть** (станция · регион · коннектор), **клиент** (тип ·
организация · карта/телефон), **процесс** (канал · исход · оплата),
**время** (день · неделя · месяц · день недели · час), **визит**.

Добавление нового разреза = запись в `GROUPS` + при необходимости подпись в
маппинге (см. `CHANNEL_RU`, `WEEKDAY_RU`) и порядок сортировки в
`DEFAULT_SORT`. UI подхватывает разрез автоматически через `/group-catalog` —
править фронт под каждый новый разрез не нужно.

## 3. Что нужно сделать

### Приоритет 1 — атрибуты станции (join к справочнику)

Новое семейство разрезов **«оборудование»**. Требует join
`charge_sessions.location_id → service_locations.id`.

⚠️ **Только через `location_id`.** Сравнение `service_locations.code =
charge_sessions.station_code` даёт 90 совпадений из 557: у CPO код обрастает
суффиксами блоков («584-1») и ведущими пробелами (CLAUDE.md, п. 12).

Разрезы:

1. **Бренд оборудования** (`brand`) — сравнение надёжности вендоров.
2. **Мощность станции** (`power_kwt`) — полосами: `≤22` · `23–49` · `50–99` ·
   `100–149` · `150+` кВт. Не сырым числом: 40 уникальных значений мощности
   разрезом не читаются.
3. **Класс скорости** (`speed_class`).
4. **Тип площадки** (`location_class`) — ТЦ / АЗС / парковка.
5. **Владелец** (`owner`) — свои против партнёрских.
6. **Протокол OCPP** (`ocpp_protocol`) — версия против доли отказов.
7. **Город** (`city`) — регион слишком крупен (Приморский край = 60 станций).
8. **Возраст станции** (`installed_on`) — полосами: `<1 года` · `1–2` · `2–3` ·
   `3+` · `не указано`. Возраст считать от **конца периода**, а не от «сегодня»:
   иначе один и тот же отчёт за прошлый год со временем меняет цифры.

### Приоритет 2 — гистограммы (binning непрерывных величин)

Семейство **«распределения»**. Отвечают на вопрос «как устроена масса», а не
«сколько всего» — сегодня в реестре нет ни одной такой.

9. **Энергия за сессию**: `0` · `0–5` · `5–10` · `10–20` · `20–40` · `40+` кВтч.
   Нулевую полосу держать отдельно: это пробы подключения, а не малые зарядки.
10. **Длительность**: `<5` · `5–15` · `15–30` · `30–60` · `60–120` · `120+` мин.
11. **Фактическая мощность** = `energy_kwh / duration_min × 60`, полосами
    как в п. 2. Считать только при `duration_min > 0` (иначе деление на ноль)
    и при `energy_kwh > 0`.
    **Главная ценность:** сопоставление с паспортной `power_kwt` станции —
    станция заявлена как 150 кВт, а выдаёт 40. Вывести в этом разрезе колонку
    «доля от паспортной» или отдельный разрез «фактическая против паспортной»
    (полосы `<30%` · `30–60%` · `60–85%` · `85%+`).
12. **Задержка оплаты** = `paid_at − finished_at`: `сразу (<5 мин)` · `<1 ч` ·
    `<1 сут` · `>1 сут` · `не оплачено`.
    ⚠️ CLAUDE.md, п. 15: «без оплаты» — три разные вещи (долг розницы,
    штатная постоплата ЮЛ, пробы без энергии). В подписи группы «не оплачено»
    это разделение не теряем — либо отдельные группы, либо колонка с разбивкой.

### Приоритет 3 — порт станции и иерархия

13. **Порт** — `station_code + connector_no` (оба 100%), подпись
    «Гоголя 1 · порт 2». Сейчас видно, что сбоит станция, но не видно, что
    сбоит конкретный разъём.
14. **Двухуровневая группировка** (drill-down path, классика BI): «Регион →
    Станция → Порт». Раскрытие строки уже есть (`/grouped/detail`), но отдаёт
    сразу сессии. Нужен промежуточный уровень: раскрытие группы верхнего
    уровня показывает подгруппы, и только их раскрытие — сессии.
    Реализовать как параметр `sub_group_by` у `/grouped` (тот же
    `ChargeGroupingService.grouped`, дополнительное условие на значение
    родительской группы).

### Приоритет 4 — колонки time intelligence

Не новые разрезы, а колонки **поверх любого существующего**:

15. **Δ к предыдущему периоду той же длины** по каждой группе.
    Эталон расчёта базы сравнения — `fuel_dashboard.py` (`cmp_from/cmp_to`,
    возвращается как `prev_period`). Границы периода включительно:
    `date_to` приводить к `T23:59:59`, иначе теряется последний день
    (CLAUDE.md, п. 8).
16. **Доля от общего** (% выручки/сессий) и **накопительная доля** —
    ABC/Парето: видно, что 20% станций дают 65% выручки.

### Приоритет 5 — поведенческие сегменты (RFM)

Обсуждалось, но приоритет ниже: это про удержание, а не про реестр сессий.
Если делать — семейство **«поведение»**: частота клиента в периоде
(`1` · `2–5` · `6–20` · `20+` сессий), новый против вернувшегося, давность
последней зарядки. Уточнить у постановщика, не логичнее ли это в разделах
«Частные лица» / «Корпоратив».

## 4. Правила достоверности (нарушение = переделка)

1. **Итог — отдельным запросом по всей выборке**, а не суммой показанных
   строк. Список групп усечён `limit`, сумма строк не сойдётся с реестром.
   Так уже сделано в `grouped()` — сохранить при доработке.
2. **«Зарядились» ≠ `result='Complete'`.** Успех считается по отпущенной
   энергии: 12 749 сессий Complete отдали 0 кВтч, 5 768 CompleteError —
   отпустили (CLAUDE.md, п. 14). Обе метрики можно показывать рядом, но
   подписывать явно.
3. **Фильтры применяются ДО свёртки.** Иначе итоги группы не сойдутся с тем,
   что видно в плоском списке. См. `_apply_filters`.
4. **`NUMERIC` → `Decimal` → в JSON строка.** Приводить `float()` на выходе,
   иначе на фронте молча ломается арифметика (CLAUDE.md, п. 16).
5. **`company_id` — в каждом запросе и в каждом ключе React Query.** Система
   мультитенантная; ключ кеша без `company_id` отдаёт данные чужой компании.
6. **Каждый параметр `queryFn` обязан быть в `queryKey`** — иначе смена
   разреза не перезапрашивает данные.
7. **Пустые значения — явной группой «не заполнено»**, а не молча
   отброшенными строками: иначе сумма групп меньше итога и это выглядит как
   потеря данных. Для полей с заполненностью 67–70% это обязательно.
8. **Сортировка по смыслу разреза.** Время — хронологически (иначе часы идут
   «03, 17, 09»), визиты — от самых многопопыточных, полосы binning — по
   возрастанию границы, а не по выручке. Механизм: `DEFAULT_SORT`.

## 5. Критерии приёмки

- [ ] Каждый новый разрез даёт **тот же итог** (сессии, энергия, выручка), что
      и остальные: разрез не меняет сумму. Проверить курлом по 3–4 разрезам.
- [ ] Разрезы по полям с неполной заполненностью показывают группу
      «не заполнено», и сумма групп равна итогу.
- [ ] `npx tsc --noEmit -p tsconfig.app.json` — 0 ошибок **в своих файлах**
      (в дереве может идти параллельная работа, чужие ошибки не чинить).
      ⚠️ `npm run build` типы НЕ проверяет — только `tsc`.
- [ ] Визуальная проверка в живом приложении: скриншот каждого нового
      семейства разрезов.
- [ ] Фактическая мощность против паспортной даёт осмысленный результат —
      привести в отчёте 3–5 худших станций.

## 6. Окружение и грабли (сэкономит час)

**Запуск.** Фронт `:3010` (`npm run dev`), бэкенд `:8000`, PG `:5435`.
Бэкенд запущен **без `--reload`** — после правки Python перезапускать:

```bash
powershell -NoProfile -Command "(Get-NetTCPConnection -LocalPort 8000 -State Listen).OwningProcess | ForEach-Object { Stop-Process -Id \$_ -Force }"
cd server && nohup "C:/Users/magsp/AppData/Local/Programs/Python/Python313/python.exe" -m uvicorn app.main:app --host 0.0.0.0 --port 8000 > /tmp/uvicorn.log 2>&1 &
# старт занимает ~30 с; готовность: curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8000/docs
```

Полный путь к интерпретатору обязателен: `python` в PATH — другой (WindowsApps),
там нет uvicorn.

**Проверка API курлом.** Логин даёт токен, компанию искать по имени:

```bash
EMAIL=$(grep '^SEED_SUPERADMIN_EMAIL=' server/.env | cut -d= -f2- | tr -d '\r')
PASS=$(grep '^SEED_SUPERADMIN_PASSWORD=' server/.env | cut -d= -f2- | tr -d '\r')
T=$(curl -s -X POST http://127.0.0.1:8000/api/auth/login -H "Content-Type: application/json" \
  -d "{\"email\":\"$EMAIL\",\"password\":\"$PASS\"}" | python -c "import sys,json;print(json.load(sys.stdin)['access_token'])")
```

⚠️ Ходить на `127.0.0.1`, а не `localhost`: бэкенд слушает только IPv4, а
`localhost` на Windows резолвится сначала в `::1` → `curl` вернёт код 000.

**Проверка в UI через Playwright.** `e2e/auth.setup.ts` **сломан**: тест
проходит, но сохраняет `storageState` без токена, и все спеки упираются в
экран входа (по 4 минуты на прогон). Обход — логин через API и токен прямо в
`localStorage`, прогон сокращается до ~15 секунд:

```ts
const api = await pwRequest.newContext({ baseURL: 'http://127.0.0.1:8000' })
const { access_token: token, user } = await (await api.post('/api/auth/login', {
  data: { email: process.env.E2E_EMAIL, password: process.env.E2E_PASSWORD },
})).json()
await page.addInitScript(([tok, uid, cid]) => {
  localStorage.setItem('clearledger-token', tok)
  localStorage.setItem(`tl-active-company-${uid}`, cid)   // cid = id РусГидро из /api/companies
}, [token, user.id, rhId])
await page.goto('./?sub=cs_list')      // прямая ссылка на реестр сессий
```

Запуск в обход сломанного setup: `npx playwright test <spec> --project=chromium --no-deps`.
Табы разреза — `role="tab"`, селектор группировки — `role="combobox"`.
Временные спеки после проверки удалять.

**Общий рабочий каталог.** В том же дереве параллельно работает другой агент
(Codex): git-индекс общий, чужие правки видны в `git status`. Перед коммитом
смотреть **весь** `git diff --cached --name-status` и коммитить только свои
файлы. Чужие ошибки typecheck не чинить.

**Язык.** Комментарии, коммиты, подписи в UI — по-русски. Коммит-сообщение
объясняет *почему*, а не пересказывает диф.
