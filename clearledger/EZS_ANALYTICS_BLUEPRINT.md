## Сквозные принципы
- KPI-полоса: 5–7 карточек, значение + **Δ% к прошлому периоду** + цвет на дельту; важное — вверх-влево (правило 5 секунд).
- График под задачу: line — время; **horizontal bar (норм. на порты)** — рейтинг; **heatmap час×день** — загрузка; таблица с data-bars/sparkline — детали. Убрать pie(много)/3D/спидометры/dual-axis.
- Тренды — YoY + пометка сезонности/неполных периодов.
- Разделять операционный (живой статус) и управленческий (тренды) слои.

## Ключевые метрики-добавки (backend)
| Метрика | Формула | Пороги/бенчмарк |
|---|---|---|
| **Utilization % (time-based)** | Σ`duration_min` ÷ (ports × дни × 24 × 60) × 100 | <10% убыточна · ~15% безубыток · 25%+ сильная |
| **Ports (порты)** | distinct(`station_code`+`connector_no`) в группе | норма для per-port метрик |
| **Throughput кВтч/день/порт** | Σ`energy_kwh` ÷ ports ÷ дни | цель EVgo 450–500 |
| **Revenue/port** | Σ`amount` ÷ ports | DCFC high: крупные суммы/год |
| **Success rate %** | визиты с отпуском энергии ÷ все визиты × 100 | основной KPI надёжности; сырой success сессий подписывать отдельно |
| **Unpaid %** | розничные сессии с `energy_kwh > 0` и без `effective_paid_at` ÷ розничные отпуски | 0,4% на снимке 17.08.2026 |
| **Payment delay** | avg(`effective_paid_at` − `finished_at`) | контроль платёжной дисциплины |
| Разрез `charge_type` | USER/RFID/ADMIN | канал запуска |
| Heatmap час×день | bucket=hour × weekday(dow) | ToU-тарифы |

## Блупринт по пунктам меню

### Обзор (стратегический слой)
KPI: Выручка · **Utilization %** · **Success %** · Сессии · Энергия · Ср.чек · **₽/кВтч** · Активных станций (все Δ к прошлому периоду).
Виджеты: мини-тренд выручки (line + оверлей прошлого периода); доли коннекторов/клиентов (гориз.bar); топ/дно станций по загрузке; алерты по ошибкам, настоящей неоплате и свежести данных.

### По станциям (рейтинг, аутсайдеры/лидеры)
Нормировать на порты. Колонки: Utilization %, кВтч/день/порт, Success %, ср.чек, ₽/кВтч + **sparkline тренда** + **data-bars** на загрузке + цвет по порогам. Дефолт-сортировка по загрузке. Топ-N + «Прочие».

### По коннекторам (для РФ ценно: CCS2/CHAdeMO/GB-T)
Таблица по типам: сессии, энергия, Utilization по типу, **Success % по типу** (найти «болеющий»), ср.энергия/сессия, AC vs DC. Решение: конфигурация портов при ремоделировании.

### Время и загрузка
Заменить бары по часам на **heatmap час × день недели** (цвет = загрузка/сессии). Пики/«мёртвые» окна → ToU-тарифы, планирование ТО.

### Клиенты и тарифы
Сегменты ФЛ/ЮЛ + **канал USER/RFID/ADMIN**; ATV и выручка по сегментам; **ценовой анализ тариф(план) vs факт `amount/energy`**; блок **платёжной дисциплины** (% без оплаты, ср.задержка).

### Динамика (тренд) — база есть
Добавить **YoY-оверлей** (линия на год) + целевую линию/бенчмарк.

### Сравнение периодов — база сильная
Добавить **пресет YoY** + метрику Utilization.

### Надёжность
Success rate; разрез исходов; success по станциям/коннекторам; тренд
надёжности; кандидаты на ТО. `error_sessions` — только явные ошибочные исходы
(`result` содержит `error` или `ошиб`), не формула «все минус Complete».

## Каноническая реализация после аудита 17.08.2026

- `services/charge_payment_state.py` — единая формула эффективной оплаты:
  `charge_sessions.paid_at` либо подтверждённый `charge_payments.bank_txn_id`.
- `analytics_service.py`, `charge_unpaid.py`, `charge_reconciliation.py`,
  `charge_grouping.py`, `overview_service.py` используют один смысл оплаты.
- Выручка ЮЛ берётся из `client_amount`, с fallback на `amount`.
- Все API аналитики, overview, реестра, корпоративной и розничной витрины требуют
  доступ к продукту `sales` через `assert_company_product`.
- `/api/analytics/charge-sessions/rows` — серверная пагинация, поиск, фильтрация,
  сортировка, итоги и фасеты. Клиентская загрузка полного реестра запрещена.
- Обзор возвращает `last_session_at`, `data_lag_days`, `is_stale`.
- Тесты-инварианты: `server/tests/test_charge_sales_regressions.py` и
  `server/tests/test_asuim_vitrina.py`.
