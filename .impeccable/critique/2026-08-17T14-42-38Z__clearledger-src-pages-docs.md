## Design Specificity Verdict

Функционально «Трек» узнаваем как полноценный контур делопроизводства: реестры, личные очереди, визирование, ознакомление, номенклатура дел, строгий доступ и юридический архив. Визуально это пока взаимозаменяемый светло-синий административный интерфейс: характер продукта создаёт терминология, а не композиция. Функциональная специфичность — 8/10, визуальная — 4/10, итоговая — 6/10.

Детерминированный detector проверил 18 TSX-файлов в `pages/docs` и `components/docs`: 0 primary, 0 advisory, false positives отсутствуют. Это подтверждает отсутствие простых механических anti-patterns, но не опровергает сценарные и IA-проблемы.

Playwright проверил пять репрезентативных маршрутов на 1440×1000 и 390×844: meaningful DOM и `main` есть везде, framework overlay и горизонтальное переполнение отсутствуют, console/page errors — 0. Пользовательский overlay не внедрялся: Browser plugin отсутствовал.

Локальный HTML-ответ вместо API признан ложным сигналом тестового окружения: Vite был запущен без backend URL. Сам этот wiring не включён в defects. Однако способы отображения уже возникшей ошибки — raw SyntaxError, ложные нули и ложный empty-state — остаются реальными дефектами UI.

## Overall Impression

Основа сильная: архитектура отвечает на реальные вопросы «что зарегистрировано», «что ждёт меня» и «где застряла работа». Самая зрелая часть — строгий доступ и юридический архив. Главная возможность — распространить их ясность, объяснение последствий и fail-closed состояния на весь остальной «Трек».

## Что работает

- Предметная IA «Реестры → На мне → Компания → Обзор» соответствует работе человека, а не структуре backend.
- Реестр сохраняет контекст в URL, использует desktop split-view и отдельную мобильную карточку.
- ACL, break-glass и архив хорошо показывают blockers, причины, доказательства и границу между удалением рабочего файла и окончательным уничтожением.
- На проверенных desktop/mobile маршрутах нет page-level overflow; статусы не кодируются только цветом.

## Priority Issues

### P1 — Навигация обещает не то, что открывает

«Метки» открывают «Виды документов» (`DocsSetupPage.tsx`), а любой пункт «Регламента» показывает сразу Представления, Расписания и Шаблоны (`TasksRegulation.tsx`). Сохранённое представление ведёт в устаревший `/tasks/company`, который перенаправляется в другой раздел. Пользователь перестаёт доверять меню.

Fix: один пункт меню должен иметь один экран и один URL-state; убрать недоступные пункты либо реализовать их, saved views перевести на актуальные docs-routes.

Suggested command: `$impeccable distill`.

### P1 — Для полноценной ежедневной работы отсутствуют несколько ключевых UI-функций

В API или модели уже есть основа, но в UI нет полного редактора вида/маршрута/полей, команды «Создать поручение по документу», рабочих saved views, меток документов и bulk-действий. Подписание/КЭП отсутствует как законченный продуктовый сценарий. Это не косметика: опытный делопроизводитель будет обходить интерфейс или обращаться к администратору.

Fix: реализовать editor вида и route, создание поручения из карточки, сохранение текущего отбора и минимальные batch-операции; по меткам и КЭП принять явное решение «реализовать или скрыть до готовности».

Suggested command: `$impeccable shape`.

### P1 — Эффективный рабочий контур не виден

Глобальный период/объекты/регионы могут присутствовать в `f=`, но «Трек» показывает только компанию и собственные локальные фильтры; Обзор отдельно создаёт 90-дневный период. Пользователь не может доказуемо ответить, к какому контуру относятся цифры и список.

Fix: постоянная строка effective scope, явное разделение global scope и local filters, единая политика периода для реестра и обзора.

Suggested command: `$impeccable clarify`.

### P1 — WCAG 2.2 AA не закрыт системно

До docs-subnav приходится пройти десятки Tab без skip-link; в shell и странице дублируются `h1`; ряд `Label` не связан с input в NewDocDialog, DocSendTab, DocExchangeBlock и DocsSetupPage. Горизонтальное mobile-меню скрывает продолжение без affordance. Detector этого не ловит, но source и Playwright подтверждают.

Fix: skip-to-content, один логический `h1`, связать label/id, проверить accessible names, добавить индикатор горизонтального продолжения и 44px touch targets для частых действий.

Suggested command: `$impeccable audit`.

### P1 — Критические действия и ошибки оформлены неодинаково

Архив и break-glass объясняют последствия и требуют доказательство; рядом «На согласование», «Ввести в действие», «Передать в архив», отклонение входящего, отзыв ссылки и прекращение замещения выполняются заметно проще. Overview и Setup способны принять API failure за нули/пустую конфигурацию; Registry и Work показывают raw exception.

Fix: единый risk-tier для действий, impact confirmation/причина/undo по политике; единый error boundary с человеческим текстом, retry и сохранением введённых данных; skeleton/unknown вместо ложных нулей.

Suggested command: `$impeccable harden`.

## Cognitive Load

Высокая: 6 провалов из 8. Работают chunking и grouping. Провалены single focus, visual hierarchy, one thing at a time, minimal choices, working memory и progressive disclosure. Главные точки перегрузки: 5–6 sibling-пунктов в разделах, 6 вкладок карточки плюс lifecycle actions и три одновременно показанные секции Регламента.

## Persona Red Flags

**Alex, опытный делопроизводитель:** нет shortcuts и batch-path; сохранённые представления не ускоряют работу; поручение нельзя создать прямо из карточки; до рабочего контента длинный Tab-путь.

**Sam, keyboard/screen reader:** несвязанные labels, дублирующиеся `h1`, отсутствие skip-link, скрытое продолжение mobile-tab bar. Плюс: archive/access alerts и текстовые статусы выполнены лучше основной оболочки.

**Jordan, новый пользователь:** три слоя навигации без объяснения, hover-only подсказки, несоответствие «Метки»/«Шаблоны» содержимому, плавающие термины «Визы/Согласование/Обработка» и технические ошибки без понятного next step.

## Minor Observations

- Mobile secondary navigation скроллится без document overflow, но не показывает, что справа есть ещё пункты.
- Архивные фильтры меняют состояние только визуально; нужны `aria-pressed` или radio semantics.
- Setup denied-state одинаков для всех пунктов и не объясняет конкретно недоступную функцию.
- При пустых данных экран визуально слишком разрежен; рабочий контур и следующий шаг должны занимать освободившееся пространство.

## Questions to Consider

- Должен ли глобальный `f=` управлять документами, или «Трек» сознательно имеет собственный scope?
- «Регламент» — это регламент поручений или единый конструктор шаблонов документов и поручений?
- Метки и КЭП входят в ближайший релиз или должны исчезнуть из интерфейса до реализации?

## Результат исполнения

Все P1 из аудита закрыты последовательными волнами. Реализованы канонические URL и
рабочий контур, состояния loading/error/403, мобильная навигация и WCAG-границы,
редактор видов, метки документов, поручения из карточки, безопасные массовые операции,
подтверждения критичных действий и provider-neutral доказательства внутренней подписи.
Интерфейс явно сообщает, что внутренняя подпись Track не является квалифицированной УКЭП.

Финальная проверка: detector — `[]`; TypeScript, ESLint и production build — успешно;
24 независимых backend-теста — успешно; Playwright — 26 маршрутов на desktop/mobile
(52 проверки), отдельно keyboard, Back/Forward, loading/403 и карточка подписи — без ошибок.
DB-интеграционный тест подписи собран, но локально не исполнен: PostgreSQL и Docker
в окружении проверки недоступны.
